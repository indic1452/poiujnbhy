# Локальная система генерации технических отчётов

Проект для телеком-компании: автоматизация подготовки технических отчётов по
обращениям заказчиков (разбор дампов протоколов, анализ оцифрованных участков
спектра, демодуляция, поиск неисправностей оборудования связи).

## Главная идея за 30 секунд

**Языковая модель не должна анализировать сигнал и не должна считать числа.**
Она должна писать текст по уже посчитанным числам.

```
дамп / IQ-запись / логи
        │
        ▼
[1] Детерминированные анализаторы          ← tshark, GNU Radio, ваши скрипты
        │   (демодуляция, разбор стека, метрики)
        ▼
[2] Факт-пакет (JSON)                      ← единственный источник чисел
        │
        ▼
[3] RAG по вашей библиотеке + прошлым отчётам
        │
        ▼
[4] Пословная генерация по секциям (локальная LLM)
        │
        ▼
[5] Верификатор: каждое число из текста обязано быть в факт-пакете
        │
        ▼
[6] Инженер правит → правки уходят в датасет → модель дообучается
        │
        ▼
    DOCX / PDF отчёт
```

Если отдать LLM «сырой дамп → готовый отчёт», вы не уберёте человеческую
ошибку, а замените её на машинную галлюцинацию, которую сложнее заметить:
цифры будут выглядеть правдоподобно. Подробности — в
[docs/01-architecture.md](docs/01-architecture.md).

## Два режима работы

**Отчёты.** Обращение заказчика → факт-пакет → черновик отчёта по шаблону →
правка инженером → подпись → DOCX. Числа только из факт-пакета, утверждение
заблокировано, пока верификатор видит ошибку.

**Помощник.** Рабочие вопросы по вашей библиотеке: как устроен кадр HDLC, какой
предел EVM для QPSK, что требует методика при измерении занимаемой полосы.
У каждого инженера свои разговоры, чужие недоступны никому. Ответ приходит
потоком, с ссылками на конкретные страницы ваших документов; если в библиотеке
ответа нет — помощник говорит об этом прямо и помечает пояснение как
непроверенное общее знание. Подробности — [docs/12](docs/12-assistant.md).

Библиотека размечается по **направлениям** (спутниковая связь, радиорелейная,
протоколы и стек OSI, модуляция, измерения, оборудование, нормативы) — это
снимает промахи вроде «уровень сигнала» вместо «уровня модели OSI». Направления
описаны в `templates/domains.json` и правятся без участия программиста:
[docs/13](docs/13-multidomain.md).

## Под какое железо это рассчитано

Сервер с **RTX 4080 (16 ГБ), Xeon E5-2680 и 64 ГБ ОЗУ** проходит этапы 0–3
дорожной карты без апгрейда: конкретные модели, кванты, ожидаемые скорости и
флаги запуска — в [docs/02, раздел 2.2](docs/02-hardware-and-models.md).
Ограничение — 16 ГБ VRAM, обходится выбором MoE-модели с выгрузкой экспертов в
оперативную память. Слой автоанализа (самая трудоёмкая часть) GPU не требует
вовсе.

## Быстрая установка на Windows

Ваш случай (RTX 4080, Windows) описан отдельно и подробно:
**[docs/11-windows.md](docs/11-windows.md)** — что скачать, как настроить видеокарту,
какие модели брать, как всё запустить и что делать, если тормозит.

Коротко:

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
cd C:\reportgen\app\scripts\windows
.\00-check.ps1       # проверка машины: GPU, драйвер, VRAM, Python, порты
.\01-install.ps1     # окружение, зависимости, настройки, администратор
.\start-all.ps1      # модель + эмбеддинги + реранкер + веб-интерфейс
```

## Что уже есть в репозитории

Работающая система целиком, кроме слоя анализа сигналов (он следующий этап).

**Ядро** — чистая стандартная библиотека Python, без зависимостей:

| Модуль | Что делает |
|---|---|
| `facts.py` | Схема факт-пакета, валидация, хеш, множество допустимых чисел |
| `corpus.py` | Нарезка библиотеки на чанки с крошками и метаданными |
| `retrieval.py` | BM25 на чистом Python, слияние ранжирований RRF |
| `llm.py` | Клиент к любому OpenAI-совместимому серверу + офлайн-заглушка |
| `pipeline.py` | Генерация отчёта по шаблону-плану, посекционно, со сшивкой |
| `verify.py` | Проверка: ни одного числа мимо факт-пакета, ссылки, структура, формулировки |

**Приложение** — поверх ядра:

| Модуль | Что делает |
|---|---|
| `store/` | SQLite: кейсы, отчёты по версиям, библиотека с индексом FTS5, векторы, датасет правок, журнал |
| `ingest/` | PDF/DOCX/MD/TXT → Markdown → чанки → база, инкрементально по SHA-256 |
| `embeddings.py`, `rerank.py`, `search.py` | Плотный поиск и реранкер на GPU, гибрид с лексическим |
| `web/` | FastAPI + интерфейс инженера на три панели (без сборки и внешних загрузок) |
| `export/docx.py` | Экспорт в DOCX по фирменному бланку |
| `dataset.py` | Выгрузка обучающего набора из правок инженеров (SFT и DPO) |
| `evaluate.py` | Эвал-харнесс: метрики из док. 05 по золотому набору |
| `cli.py` | `serve`, `useradd`, `ingest`, `embed`, `library`, `dataset`, `eval`, `stats` и файловые команды |

Плюс `scripts/windows/` — PowerShell для установки, запуска, автозапуска и
резервного копирования на Windows.

## Быстрый старт без GPU (проверить конвейер на заглушке)

```bash
./run.sh index --corpus examples/corpus --out build/index.json

./run.sh check-facts --facts examples/cases/case-2024-118.json \
                     --outline templates/outline_signal_issue.json

./run.sh generate --facts examples/cases/case-2024-118.json \
                  --outline templates/outline_signal_issue.json \
                  --index build/index.json \
                  --out build/report.md \
                  --llm stub --glossary templates/glossary.json

./run.sh verify --facts examples/cases/case-2024-118.json \
                --report build/report.md \
                --outline templates/outline_signal_issue.json
```

Запуск с реальной локальной моделью — то же самое, но:

```bash
./run.sh generate ... --llm openai \
    --base-url http://127.0.0.1:8000/v1 --model qwen3-14b
```

`--llm openai` означает лишь «OpenAI-совместимый HTTP API»: так говорят
llama.cpp, Ollama, vLLM и SGLang. Наружу ничего не уходит.

Тесты:

```bash
PYTHONPATH=src:tests python3 -m unittest discover -s tests -v
```

## С чего начать

1. Прочитать [docs/01](docs/01-architecture.md) — принять или оспорить главное
   архитектурное решение (числа из кода, текст из модели).
2. Провести инвентаризацию данных по таблице из [docs/03, раздел 3.1](docs/03-data-and-training.md).
3. Выбрать 2–3 самых частых типа обращений и написать под них шаблоны-планы по
   образцу `templates/outline_signal_issue.json`. Пишет их старший инженер, не программист.
4. Зафиксировать словарь ключей измерений ([docs/08](docs/08-fact-pack.md)) — это контракт,
   менять его потом дорого.
5. Начать кодировать слой автоанализа ([docs/06](docs/06-roadmap.md), этап 1). Это даёт выигрыш
   времени само по себе, ещё до генерации текста.
