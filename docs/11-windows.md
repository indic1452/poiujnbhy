# 11. Установка на Windows (RTX 4080, всё на GPU)

Пошаговая инструкция для одной машины: Windows 10/11, NVIDIA RTX 4080 16 ГБ,
Xeon E5-2680, 64 ГБ ОЗУ. После установки у вас будет:

- языковая модель, работающая **на видеокарте**, на `http://127.0.0.1:8000`;
- поиск по вашей технической библиотеке с ускорением на GPU (эмбеддинги +
  реранкер) на портах 8001 и 8002;
- веб-интерфейс инженера на `http://127.0.0.1:8080`;
- автозапуск всего этого при входе в систему.

Время установки — примерно 1.5–2 часа, из них большая часть уходит на
скачивание моделей (15–25 ГБ).

Все команды выполняются в **PowerShell**. Открыть: `Win+X` → «Терминал» или
«Windows PowerShell». Где нужен запуск от администратора — это указано отдельно.

## Шаг 0. Настройка видеокарты — не пропускайте

Три настройки, без которых всё будет работать, но медленно. Первая — самая
важная: без неё Windows молча начнёт «доливать» видеопамять из обычного ОЗУ,
и скорость упадёт в 5–10 раз, причём **без единого сообщения об ошибке**.

1. **Панель управления NVIDIA** (правый клик по рабочему столу) →
   «Управление параметрами 3D» → вкладка «Глобальные параметры»:
   - **CUDA — резервный вариант системной памяти** (CUDA — Sysmem Fallback
     Policy) → **«Предпочтительно без резервной системной памяти»**
     (Prefer No Sysmem Fallback). Теперь при нехватке VRAM вы получите честную
     ошибку вместо десятикратного замедления.
   - **Режим управления электропитанием** → «Предпочтителен режим максимальной
     производительности».
   - Нажмите «Применить».

2. **Электропитание Windows**: `Параметры` → `Система` → `Питание` →
   схема «Максимальная производительность» (или `powercfg /s SCHEME_MIN`
   в PowerShell от администратора).

3. **Защитник Windows**: исключите каталог с моделями из проверки, иначе
   антивирус будет сканировать файлы по 10–20 ГБ при каждом запуске.
   В PowerShell **от администратора**:

   ```powershell
   Add-MpPreference -ExclusionPath 'C:\reportgen'
   ```

Проверьте, что видеокарта видна:

```powershell
nvidia-smi
```

Должны увидеть `NVIDIA GeForce RTX 4080`, версию драйвера и `16376MiB`.
Если команда не найдена — установите драйвер (шаг 1, пункт 1) и перезагрузитесь.

> **Сколько памяти реально доступно.** Из 16 ГБ рабочий стол Windows,
> браузер и мессенджеры забирают 0.7–1.5 ГБ. Рассчитывайте примерно на
> **14.5 ГБ** под модели. Если во время работы запускать игры или тяжёлые
> 3D-приложения — модель выгрузится и придётся перезапускать сервер.

## Шаг 1. Что скачать

| Что | Где | Зачем | Размер |
|---|---|---|---|
| Драйвер NVIDIA 550+ | [nvidia.com/Download](https://www.nvidia.com/Download/index.aspx) | Поддержка CUDA 12.4 | ~700 МБ |
| llama.cpp, сборка под Windows + CUDA | [github.com/ggml-org/llama.cpp/releases](https://github.com/ggml-org/llama.cpp/releases) | Сервер, который крутит модель на GPU | ~200 МБ |
| CUDA runtime для llama.cpp | там же, файл `cudart-llama-bin-win-cu12.*-x64.zip` | Библиотеки CUDA, без них сервер не стартует | ~300 МБ |
| Python 3.11 или 3.12 | [python.org/downloads/windows](https://www.python.org/downloads/windows/) | Само приложение | ~25 МБ |
| Git для Windows (по желанию) | [git-scm.com/download/win](https://git-scm.com/download/win) | Обновления кода одной командой | ~60 МБ |
| 7-Zip (по желанию) | [7-zip.org](https://www.7-zip.org/) | Распаковка больших архивов | ~1.5 МБ |
| Модели GGUF | huggingface.co, см. шаг 4 | Собственно нейросети | 12–25 ГБ |

**Про архив llama.cpp.** В списке файлов релиза берите тот, в имени которого
есть одновременно `win`, `cuda` и `x64` — например
`llama-b6100-bin-win-cuda-12.4-x64.zip`. Файлы с `cpu`, `vulkan`, `hip`,
`arm64` вам не нужны: `cpu` не использует видеокарту, `vulkan` медленнее CUDA
на NVIDIA. **Обязательно скачайте вторым файлом `cudart-...`** — это
библиотеки CUDA, которые кладутся рядом с `llama-server.exe`.

При установке Python обязательно отметьте галочку
**«Add python.exe to PATH»** на первом экране установщика.

## Шаг 2. Каталоги и распаковка

Создайте структуру (PowerShell):

```powershell
mkdir C:\reportgen, C:\reportgen\llama, C:\reportgen\models, C:\reportgen\data, C:\reportgen\logs
```

Распакуйте **оба** архива llama.cpp в `C:\reportgen\llama` — сначала основной,
потом `cudart` поверх (согласитесь на замену). В итоге в каталоге должны лежать
`llama-server.exe`, `llama-cli.exe` и десятка полтора `.dll`, среди которых
`cudart64_12.dll`, `cublas64_12.dll`, `ggml-cuda.dll`.

Проверьте, что сервер видит видеокарту:

```powershell
C:\reportgen\llama\llama-server.exe --list-devices
```

В выводе должна быть строка вида `CUDA0: NVIDIA GeForce RTX 4080 (16376 MiB)`.
Если написано только `CPU` — вы распаковали сборку без CUDA либо не положили
рядом `cudart`.

## Шаг 3. Код приложения

Если установлен Git:

```powershell
cd C:\reportgen
git clone <адрес-вашего-репозитория> app
```

Без Git — скачайте архив репозитория с GitHub («Code» → «Download ZIP») и
распакуйте так, чтобы получилось `C:\reportgen\app\src\reportgen\...`.

Разрешите выполнение скриптов (один раз, для текущего пользователя):

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

Проверьте машину и установите приложение:

```powershell
cd C:\reportgen\app\scripts\windows
.\00-check.ps1
.\01-install.ps1
```

`01-install.ps1` создаст виртуальное окружение Python, поставит зависимости,
подготовит `C:\reportgen\settings.json` и спросит логин создателя системы
(пароль — не короче 8 символов, вводится скрыто). Заводится он с должностью
`owner`: полные права, отключить или разжаловать эту запись нельзя. Остальных
сотрудников заводят потом — шаг 9.

## Шаг 4. Модели

### 4.1. Какую основную модель брать

На 16 ГБ VRAM разумны два варианта. Начните с первого, через неделю работы
сравните со вторым на своих отчётах — это полчаса работы и один запуск.

| Вариант | Что это | Размер файла | Скорость на 4080 | Когда выбирать |
|---|---|---|---|---|
| **A. Qwen3-14B, квант Q5_K_M** | Плотная модель, целиком помещается в видеопамять | ~10.5 ГБ | 40–55 токенов/с | По умолчанию. Быстро, хороший русский, влезает целиком |
| **B. Qwen3-30B-A3B, квант Q4_K_M** | MoE: 30 млрд параметров, но активны только 3 млрд | ~18.5 ГБ | 20–30 токенов/с | Когда качество текста важнее скорости. Часть весов уходит в ОЗУ |

Отчёт на 7 разделов (примерно 3 тысячи слов) при 40 ток/с собирается за
**2–3 минуты**, при 25 ток/с — за **4–5 минут**. Это с учётом того, что
разделы генерируются по очереди.

Не берите: модели крупнее 32B (не влезут), кванты ниже Q4 (заметно врут в
формулировках), кванты выше Q6 для 14B (не влезут вместе с контекстом).

### 4.2. Модели для поиска по библиотеке

Обе маленькие, работают на той же видеокарте и вместе занимают около 1.4 ГБ:

| Модель | Назначение | Файл |
|---|---|---|
| **bge-m3** | Эмбеддинги: понимает смысл запроса, а не только слова | ~0.65 ГБ (Q8_0) |
| **bge-reranker-v2-m3** | Реранкер: выбирает из 50 найденных фрагментов 6 действительно нужных | ~0.65 ГБ (Q8_0) |

Реранкер — самая выгодная по соотношению «усилие/качество» часть системы:
именно он отвечает за то, чтобы модель писала со ссылкой на нужную страницу
даташита, а не на случайно похожий абзац.

### 4.3. Как скачать

Способ первый — llama.cpp скачает сам при первом запуске:

```powershell
cd C:\reportgen\llama
.\llama-server.exe -hf Qwen/Qwen3-14B-GGUF:Q5_K_M --port 8000
```

Файл ляжет в кэш HuggingFace; чтобы он оказался в вашем каталоге, удобнее
второй способ — скачать явно:

```powershell
C:\reportgen\app\.venv\Scripts\python.exe -m pip install huggingface_hub
C:\reportgen\app\.venv\Scripts\hf.exe download Qwen/Qwen3-14B-GGUF `
    --include "*Q5_K_M*.gguf" --local-dir C:\reportgen\models
```

Третий способ — вручную: открыть страницу модели на huggingface.co, вкладка
**Files**, найти нужный `.gguf` и нажать «download». Так надёжнее всего, если
скачивание через прокси.

> **Имена репозиториев меняются.** Ищите на huggingface.co по запросам
> `Qwen3-14B GGUF`, `Qwen3-30B-A3B GGUF`, `bge-m3 GGUF`,
> `bge-reranker-v2-m3 GGUF` и берите репозиторий с наибольшим числом
> скачиваний. Внутри выбирайте файл, в имени которого есть нужный квант
> (`Q5_K_M`, `Q4_K_M`, `Q8_0`). Если модель разрезана на части
> (`-00001-of-00003.gguf`) — качайте все части в один каталог, llama.cpp
> соберёт их сам по первому файлу.

В итоге в `C:\reportgen\models` должно лежать примерно так:

```
Qwen3-14B-Q5_K_M.gguf          10.5 ГБ
bge-m3-Q8_0.gguf                0.65 ГБ
bge-reranker-v2-m3-Q8_0.gguf    0.65 ГБ
```

Скрипты сами найдут нужные файлы по именам: основной моделью считается самый
большой `.gguf`, в имени которого нет `bge`, `embed` или `rerank`.

## Шаг 5. Настройки

Откройте `C:\reportgen\settings.json` в «Блокноте» и поправьте раздел
оформления — это то, как система будет выглядеть у вас:

```json
"brand_name": "Ваша компания",
"brand_subtitle": "Отдел технической экспертизы",
"brand_accent": "#2563eb",
"brand_logo": "C:\\reportgen\\logo.png",
"report_footer": "Технический отчёт. Не является офертой."
```

`brand_accent` — цвет кнопок и акцентов в интерфейсе (любой HEX).
`brand_logo` — путь к PNG или SVG высотой от 64 пикселей; если логотипа нет,
поставьте `null`.

Фон окна входа настраивать не нужно: в поставке лежит кадр со спутником и
Землёй. Свой снимок подхватится сам, если положить файл рядом с
`settings.json` под именем `login-bg.jpg` (годятся также `.jpeg`, `.png`,
`.webp`). Отдельный путь при этом не нужен — у всех установок он был бы разный,
а имя одно.

Остальное можно не трогать. Что стоит знать:

| Ключ | Смысл |
|---|---|
| `port` | Порт веб-интерфейса, по умолчанию 8080 |
| `host` | `127.0.0.1` — доступ только с этой машины. Для доступа коллег см. шаг 9 |
| `auth_enabled` | `true` — вход по логину и паролю. Выключать только на изолированной машине |
| `embed_enabled` / `rerank_enabled` | Использовать GPU-поиск. Оставьте `true` |
| `retrieval_top_k` | Сколько фрагментов библиотеки подаётся модели на раздел отчёта (8) |
| `assistant_context_chars` | Сколько знаков найденного материала помощник кладёт в один вопрос (26000). Связано с размером контекста модели — см. шаг 6 |
| `llm_timeout` | Сколько секунд ждать ответ модели. 900 — с запасом |
| `docx_template` | Путь к вашему фирменному бланку `.docx`. Из него подхватятся стили и колонтитулы |

Остальные ключи `assistant_*` (`assistant_top_k`, `assistant_source_chars`,
`assistant_neighbours`, `assistant_neighbour_top`, `assistant_outlines`,
`assistant_attachment_chars`, `assistant_max_tokens`, `assistant_target_words`)
подобраны под окно контекста из шага 6 и под нарезку библиотеки. Что каждый из
них делает — в [docs/12-assistant.md](12-assistant.md); менять их поодиночке
без нужды не стоит.

## Шаг 6. Первый запуск

Одна команда поднимает всё:

```powershell
cd C:\reportgen\app\scripts\windows
.\start-all.ps1
```

Для варианта B (модель 30B-A3B) добавьте выгрузку части экспертов в ОЗУ:

```powershell
.\start-all.ps1 -CpuMoe 10
```

Что произойдёт:

1. В отдельном окне поднимется `llama-server` с основной моделью. Первый
   запуск занимает 40–120 секунд: модель читается с диска в видеопамять.
2. Свернутыми окнами поднимутся эмбеддер (8001) и реранкер (8002).
3. Запустится веб-приложение и откроется браузер на `http://127.0.0.1:8080`.

Войдите под логином создателя системы, который задали при установке. Откроется
раздел «Дашборд»; остальные разделы — «Письма», «Помощник», «Библиотека»,
«Метрики», «Сотрудники» — в боковом меню слева.

Проверьте загрузку видеопамяти в соседнем окне PowerShell:

```powershell
nvidia-smi
```

Должно быть занято 12–14.5 ГБ из 16. Если занято меньше 8 ГБ — модель
считается на процессоре, смотрите раздел «Что делать, если медленно».

### Размер контекста

`start-llm.ps1` поднимает модель с `-c 32768 --parallel 2`: два слота по
16384 токена, то есть на один разговор с помощником приходится половина окна.
Столько нужно, чтобы уложить найденный материал (до 26 000 знаков),
системную инструкцию и оставить 4000 токенов на ответ.

Уменьшать контекст, не трогая настройки помощника, нельзя. О переполнении окна
llama.cpp не сообщает никак: начало промпта молча выбрасывается вместе с
системной инструкцией, и модель перестаёт ставить ссылки на источники, начиная
отвечать по памяти. Со стороны это выглядит как «модель поглупела».

Если видеопамяти не хватает и сервер падает при запуске, снижайте контекст
ступенями и вместе с ним — `assistant_context_chars` в `settings.json`:

| `-Context` | `assistant_context_chars` |
|---|---|
| 32768 (по умолчанию) | 26000 |
| 24576 | 18000 |
| 16384 | 11000 |

Ключ передаётся и через `start-all.ps1`: `.\start-all.ps1 -Context 24576`.

Чего контекст стоит по памяти: KV-кэш (скрипт запускает сервер с
`--cache-type-k q8_0` и `--cache-type-v q8_0`) — около 85 КБ на токен, то есть
32768 токенов занимают примерно 2.8 ГБ. Вместе с моделью Qwen3-14B Q5_K_M
(10.5 ГБ) и рабочими буферами это около 14.4 ГБ из 16.

### Подбор `-CpuMoe` для MoE-модели

Флаг говорит, сколько слоёв «экспертов» держать в обычной оперативной памяти.
Чем меньше значение, тем быстрее, но тем больше занято VRAM. Подбирается за
три-четыре запуска:

1. Запустите с `-CpuMoe 14`, посмотрите `nvidia-smi`.
2. Занято меньше 13.5 ГБ — уменьшайте на 2 и перезапускайте.
3. Появилась ошибка `CUDA error: out of memory` — увеличьте на 2.
4. Остановитесь на значении, при котором занято 14–14.5 ГБ.

Для плотной модели (вариант A) `-CpuMoe` не нужен вообще.

## Шаг 7. Библиотека и индексация

1. Разложите файлы по каталогам (PDF, DOCX, TXT, Markdown):

```
C:\reportgen\data\library\
    literature\    книги, конспекты, учебники
    standards\     ГОСТ, РД, рекомендации ITU/ETSI
    datasheets\    даташиты и руководства на оборудование
    reports\       прошлые отчёты (обезличенные)
    regulations\   внутренние регламенты, глоссарий
```

2. Загрузите — одной командой, она делает разбор, векторы и отчёт:

```powershell
cd C:\reportgen\app\scripts\windows
.\load-library.ps1
```

Скорость — примерно 2–10 страниц PDF в секунду; библиотека на 5 тысяч страниц
обрабатывается за 10–20 минут. Сканы без текстового слоя распознаются
tesseract'ом — это 2–5 секунд на страницу, поэтому большую пачку сканов лучше
запускать на ночь.

Раскладывать по папкам необязательно: тип берётся из имени каталога верхнего
уровня, а если каталог назван по-своему — определяется по самому документу.
Что не опознано, попадает на полку «Прочее», где его видно и можно разобрать
руками. Подробно о том, что в какую папку класть и как разметить документы по
направлениям, — в [docs/18-library.md](18-library.md).

3. Проверьте, что поиск находит нужное: откройте в интерфейсе раздел
«Библиотека» и введите запрос в строку проверки поиска. Поиск по установленной
системе идёт по базе, отдельный файл индекса для этого не нужен.

```powershell
Invoke-Reportgen stats        # сколько документов и фрагментов в базе
Invoke-Reportgen library      # что именно загружено и с какими предупреждениями
```

Команда `Invoke-Reportgen search` — из другого, файлового конвейера: она ищет по
индексу, собранному командой `index` из каталога с текстами, и к базе отношения
не имеет. Если по осмысленному запросу выдаётся ерунда — дело почти
всегда в плохо распознанных PDF, а не в модели.

Дальше документы можно добавлять прямо через интерфейс: перетащить файл в
раздел «Библиотека», он сразу проиндексируется.

## Шаг 8. Автозапуск

```powershell
cd C:\reportgen\app\scripts\windows
.\register-autostart.ps1            # для MoE: .\register-autostart.ps1 -CpuMoe 10
```

Комплекс будет подниматься при входе пользователя в систему. Отключить:

```powershell
.\register-autostart.ps1 -Remove
```

Остановить всё вручную:

```powershell
.\stop-all.ps1
```

## Шаг 9. Доступ коллег по сети (необязательно)

По умолчанию система слушает только `127.0.0.1` — снаружи её не видно. Чтобы
к ней могли подключаться другие инженеры отдела:

1. В `settings.json` поставьте `"host": "0.0.0.0"`.
2. Разрешите порт в брандмауэре (PowerShell **от администратора**):

```powershell
New-NetFirewallRule -DisplayName "Reportgen 8080" -Direction Inbound `
    -Protocol TCP -LocalPort 8080 -Action Allow -Profile Domain,Private
```

3. Убедитесь, что `"auth_enabled": true`. В письмах лежат служебные материалы —
   открывать их в сеть без входа по паролю нельзя.
4. Заведите коллегам учётные записи:

```powershell
cd C:\reportgen\app\scripts\windows
.\users.ps1                                                  # кто уже заведён
.\users.ps1 -Add petrov -Role engineer -Name "Петров П. П." `
    -Department "Отдел радиосвязи" -Team "1 группа"          # новый сотрудник
```

Должности повторяют штатное расписание, а не уровни доступа:

| `-Role` | Должность | Права |
|---|---|---|
| `owner` | Создатель системы | Полные. Отключить и разжаловать эту запись нельзя |
| `head` | Начальник отдела | Администратор |
| `deputy` | Заместитель начальника отдела | Администратор |
| `lead` | Начальник группы | Администратор |
| `senior` | Старший инженер отдела | Письма, отчёты, библиотека |
| `engineer` | Инженер отдела | Письма, отчёты, библиотека |

Права администратора — сотрудники, удаление документов, журнал действий — у
должностей до начальника группы включительно. Письма и отчёты ведут все
должности: разделения на «смотрящих» и «работающих» больше нет, в отделе такой
должности не существует.

Менять чужую запись — должность, отдел, группу, пароль — можно только
сотруднику младше себя по должности. Начальник группы не переназначит
начальника отдела, а заместитель — создателя системы. Свою запись каждый
правит сам. Запись создателя системы в интерфейсе не меняет никто, включая
его самого: иначе установка рискует остаться без владельца, а чинить это на
изолированной машине нечем. Пароль ему меняют с самой машины, скриптом
`users.ps1 -Reset` — см. ниже.

`-Role` без значения означает `owner`: скрипт рассчитан на то, что первым
заводят именно создателя системы. Для коллег должность указывайте явно.
`-Department` и `-Team` необязательны. Заполнить их стоит сразу: группа
подписывается рядом с фамилией в списке нагрузки на дашборде, и по ней видно,
кому раздавать письма. Позже отдел и группу правят в разделе «Сотрудники».

Коллеги заходят на `http://<имя-компьютера>:8080`.

### Забыт пароль

Пароль хранится только в виде хеша, восстановить его нельзя — можно задать
новый. Старый для этого не нужен: это администрирование на самой машине.

```powershell
cd C:\reportgen\app\scripts\windows
.\users.ps1 -Reset admin
```

Скрипт спросит новый пароль (не короче 8 символов, вводится скрыто) и закроет
все активные сессии этого пользователя.

Если в системе вообще нет ни одного сотрудника — например, установка
оборвалась до его создания — заведите создателя системы заново:

```powershell
.\users.ps1 -Add admin
```

Должность указывать не нужно: без `-Role` скрипт заводит `owner`.

## Резервное копирование

```powershell
cd C:\reportgen\app\scripts\windows
.\backup.ps1
```

Копия ложится в `C:\reportgen\backups\<дата>\`: база данных (снимается «на
горячую», приложение останавливать не нужно, целостность проверяется),
архив библиотеки, экспортированные отчёты и настройки. Хранятся последние
14 копий.

Поставьте это в планировщик задач на ночь — база маленькая, копия делается
за секунды. Восстановление: остановить приложение, положить `reportgen.db`
обратно в `C:\reportgen\data\`, распаковать `library.zip`.

**Что невосстановимо, если потеряется:** база (письма, отчёты, накопленные
правки инженеров, учётные записи) и библиотека. Индексы и векторы
пересобираются из библиотеки командами `ingest` и `embed`.

## Обновление

Код приложения:

```powershell
cd C:\reportgen\app
git pull
.\scripts\windows\01-install.ps1 -SkipDeps    # или без флага, если менялись зависимости
```

> **После обновления кода переиндексируйте библиотеку.** Правила разбиения
> текста на токены иногда меняются (например, номера пунктов «5.3.2» перестали
> распадаться на три числа). Индекс, построенный старыми правилами, ищется
> хуже — но молча. Команда: `reportgen ingest --force`, затем `reportgen embed`.

Переиндексация на Windows:

```powershell
cd C:\reportgen\app\scripts\windows
. .\_common.ps1
Invoke-Reportgen ingest --force
Invoke-Reportgen embed --force
```

> **Должности переносятся сами.** База, заведённая до перехода на штатные
> должности, обновляется при первом запуске: первый по счёту администратор —
> тот, кто разворачивал систему, — становится создателем системы (`owner`),
> остальные администраторы — начальниками отдела (`head`), а прежние
> «наблюдатели» — инженерами отдела (`engineer`). Прав никто не теряет.
> Отдел и группу проставьте руками в разделе «Сотрудники»: угадать их
> система не может.

llama.cpp: скачать новый архив релиза, остановить всё (`.\stop-all.ps1`),
распаковать поверх `C:\reportgen\llama`, запустить снова. Скрипты сами
определят, какие флаги поддерживает новая сборка.

Модель: положить новый `.gguf` в `C:\reportgen\models`, указать его в
`settings.json` (`llm_model_file`) либо передать в запуске:
`.\start-all.ps1 -Model "Новая-модель-Q4_K_M.gguf"`. Старую модель не удаляйте
неделю — вдруг новая окажется хуже на ваших отчётах.

## Что делать, если что-то не так

### Медленно (меньше 10 токенов в секунду)

Почти всегда это одно из двух:

1. **Не отключён Sysmem Fallback** (шаг 0). Проверка: `nvidia-smi` показывает
   занятыми почти все 16 ГБ и при этом всё равно тормозит. Отключите и
   перезапустите модель.
2. **Модель не влезла в видеопамять** и часть слоёв считается на процессоре.
   В окне `llama-server` при старте видно строку вида
   `offloaded 40/49 layers to GPU` — если не все слои, возьмите квант меньше
   (Q4_K_M вместо Q5_K_M) или снизьте контекст на ступень (`-Context 24576`),
   не забыв про `assistant_context_chars` — см. «Размер контекста» в шаге 6.

Другие причины: открыт браузер с десятком вкладок и аппаратным ускорением
(съедает VRAM), включён режим энергосбережения, запущены две копии модели
одновременно.

### `CUDA error: out of memory`

Уменьшите нагрузку в таком порядке: контекст на одну ступень (`-Context 24576`,
затем `16384`) вместе с `assistant_context_chars`, затем квант модели, затем
для MoE увеличьте `-CpuMoe`. Ступени и соответствие — в шаге 6, «Размер
контекста». Проверьте, что не запущены одновременно два `llama-server` с
большой моделью: `.\stop-all.ps1`.

### Кириллица в консоли выглядит как «??????»

```powershell
chcp 65001
```

Или используйте «Терминал Windows» — он по умолчанию в UTF-8.

### `... не удаётся загрузить, так как выполнение сценариев отключено`

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

### `llama-server.exe` запускается и сразу закрывается

Запустите его вручную из PowerShell (`.\start-llm.ps1`), чтобы увидеть текст
ошибки. Типичное: не распакован `cudart` (жалуется на отсутствие
`cudart64_12.dll`), не найден файл модели, занят порт 8000.

### Порт занят

```powershell
Get-NetTCPConnection -LocalPort 8080 | Select-Object OwningProcess
Get-Process -Id <номер>
```

Либо просто `.\stop-all.ps1`.

### Поиск не находит очевидные вещи

Проверьте, что документы вообще проиндексировались: в разделе «Библиотека»
у каждого документа указано число фрагментов. Ноль фрагментов у PDF означает
скан без текстового слоя — нужен OCR. Если фрагменты есть, а поиск плохой —
запустите `Invoke-Reportgen embed` (векторы не построены) и убедитесь, что
`embed_enabled` и `rerank_enabled` равны `true`, а порты 8001 и 8002 отвечают.

### Модель пишет ерунду или уходит в англоязычный текст

Проверьте, что скачали именно `instruct`-вариант модели, а не базовый
(`base`). Базовые модели не умеют следовать инструкциям.

### Помощник перестал ставить ссылки на источники

Обычный признак переполненного окна контекста: llama.cpp не сообщает о
переполнении, а молча выбрасывает начало промпта вместе с системной
инструкцией — вместе с ней уходит и требование ссылаться на источники.
Посмотрите в окне `llama-server` строку запуска (скрипт печатает её перед
стартом): там должны быть `-c 32768` и `--parallel 2`. Если контекст
понижали, приведите `assistant_context_chars` в `settings.json` в
соответствие с таблицей из шага 6.

### Верификатор блокирует отчёт из-за числа, которого «нет в факт-пакете»

Это работает как задумано: модель не имеет права называть числа, которых нет
в исходных данных. Либо число действительно выдумано (тогда правьте текст),
либо оно должно быть в факт-пакете — добавьте измерение в левой панели и
перегенерируйте раздел.

### Приложение запускается, но интерфейс пустой

Откройте `http://127.0.0.1:8080/api/health`. Если API отвечает, а страница
пустая — очистите кэш браузера (`Ctrl+F5`). Если API не отвечает, смотрите
окно, в котором запущено приложение, и `C:\reportgen\logs\`.
