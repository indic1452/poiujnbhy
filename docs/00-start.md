# 00. С нуля до работы: весь путь

Этот документ — один сквозной маршрут: две машины, внешний диск и список
команд по порядку. Всё остальное в `docs/` — подробности к отдельным шагам;
сюда вынесено то, что нужно делать, и в каком порядке.

Читать целиком не обязательно. Найдите свой случай:

| Ваше положение | Куда идти |
|---|---|
| Ничего ещё нет, ставлю первый раз | [Шаг 1](#шаг-1-что-понадобится) и дальше по порядку |
| Система установлена, надо загрузить документы | [Шаг 7](#шаг-7-загрузить-библиотеку) |
| Система работает, хочу добавить RFC | [Шаг 6](#шаг-6-rfc-архив-описаний-протоколов) |
| Вышло обновление, надо перенести | [Шаг 9](#шаг-9-обновление-кода) |
| Что-то не работает | [Шаг 10](#шаг-10-если-что-то-пошло-не-так) |

## Шаг 1. Что понадобится

**Две машины.**

| | Машина с интернетом | Рабочая машина (офлайн) |
|---|---|---|
| Зачем | скачать всё один раз | здесь система работает |
| Требования | Windows, ~25 ГБ свободно, Git, PowerShell | Windows 10/11, RTX 4080 (16 ГБ), 64 ГБ ОЗУ, 200 ГБ на диске |
| Интернет | нужен | не нужен никогда |

**Внешний диск от 32 ГБ.** Комплект — около 19 ГБ, RFC — ещё 0,5 ГБ, ваша
библиотека — сколько есть.

Проверить рабочую машину заранее можно и без установки: скопируйте на неё
`scripts\windows\00-check.ps1` и запустите. Он скажет про видеокарту,
драйвер, память и место на диске.

## Шаг 2. На машине с интернетом: скачать всё

```powershell
git clone <адрес-репозитория> reportgen
cd reportgen\scripts\offline
powershell -ExecutionPolicy Bypass -File .\pack.ps1 -Probe
```

`-Probe` ничего не качает — за полминуты проверяет, что все адреса живы.
Читайте вывод: строка `недоступно источников: 0` означает, что можно
запускать сборку. Если что-то недоступно, см. [шаг 10](#шаг-10-если-что-то-пошло-не-так).

```powershell
powershell -ExecutionPolicy Bypass -File .\pack.ps1 -Destination D:\reportgen-offline
```

Это несколько часов и ~19 ГБ. Скачивается **всё**: модели, сборка llama.cpp,
Python, Git, LibreOffice, Tesseract с языковыми файлами, DjVuLibre, 7-Zip,
Visual C++ Redistributable, все пакеты Python колёсами, исходники и
документация. Руками искать ничего не нужно.

Прервалось — запустите ту же команду снова: уже скачанное не перекачивается.

Подробности: [docs/15-offline.md](15-offline.md).

## Шаг 3. Перенести на рабочую машину

Скопируйте каталог `D:\reportgen-offline` целиком на внешний диск, а с него —
на рабочую машину, например в `C:\install\reportgen-offline`.

Архивировать не нужно и вредно: модели уже сжаты, а одна ошибка чтения в
архиве на 19 ГБ обесценивает весь перенос.

## Шаг 4. Установить

```powershell
cd C:\install\reportgen-offline
.\verify.ps1
```

Проверка SHA-256 каждого файла, несколько минут. Должно закончиться словами
**«Комплект целый»**. Если нет — перенесите повреждённые файлы заново, ставить
нельзя.

Дальше — PowerShell **от имени администратора**:

```powershell
cd C:\install\reportgen-offline
.\install-offline.ps1
```

Установщик поставит Python и все программы, развернёт код в `C:\reportgen\app`,
распакует модели, соберёт окружение из колёс, проверит себя и предложит завести
создателя системы — учётную запись с полными правами (логин и пароль). Сеть при
этом не используется ни разу.

В конце он печатает список замечаний, если они были, и что делать дальше.
Замечание — это не отказ: установка продолжается, а вы видите, что именно
осталось доделать.

> **Один шаг руками.** В панели управления NVIDIA отключите «резервную
> системную память CUDA» (`Управление параметрами 3D` → `Резервная системная
> память CUDA` → `Предпочитать отсутствие резервной системной памяти`). Без
> этого драйвер при нехватке видеопамяти начинает тихо использовать
> оперативную, и модель работает в десятки раз медленнее вместо честной
> ошибки. Подробно — [docs/11-windows.md](11-windows.md), шаг 0.

## Шаг 5. Первый запуск

```powershell
cd C:\reportgen\app\scripts\windows
.\00-check.ps1
.\start-all.ps1
```

`00-check.ps1` проверяет машину и настройки. `start-all.ps1` поднимает три
службы: языковую модель, эмбеддер с реранкером и веб-приложение. Первый запуск
дольше обычного — модель читается с диска в видеопамять.

Модель поднимается с окном контекста `-c 32768` и `--parallel 2`: окно делится
между слотами, то есть на один разговор приходится 16384 токена. Меньше без нужды
брать не стоит: помощник кладёт в вопрос до 26 000 знаков найденного материала и
оставляет 4000 токенов на ответ; если это не помещается, llama.cpp не ругается, а
молча выбрасывает начало промпта вместе с системной инструкцией — и модель
перестаёт ставить ссылки на источники. Со стороны это выглядит как «модель
поглупела», хотя причина в переполненном окне. Если видеопамяти не хватает и
сервер падает при запуске, снижайте контекст ступенями — `-Context 24576`, затем
`-Context 16384` — и вместе с ним `assistant_context_chars` в `settings.json`
(26000 → 18000 → 11000):

```powershell
.\start-all.ps1 -Context 24576
```

Откройте <http://127.0.0.1:8080> и войдите под учётной записью создателя системы.

Слева — боковое меню: **Сводка** (что в отделе сегодня), **Письма**
(входящие письма и ответы на них), **Расход** (кто на месте, кто в наряде),
**Сообщения** (переписка между людьми отдела), **Помощник** (вопрос-ответ по
библиотеке), **Библиотека**, **Метрики** и **Военнослужащие**. Последний виден только
должностям с правами администратора. Содержимое занимает всю ширину монитора —
на широком экране таблица писем и три панели помощника видны целиком.

Остановить всё: `.\stop-all.ps1`.
Запускать при входе в систему автоматически: `.\register-autostart.ps1`.

### Военнослужащие

```powershell
.\users.ps1                                        # личный состав
.\users.ps1 -Add petrov -Name "Петров П. П." -Role senior -Department "2 специальный отдел"
.\users.ps1 -Reset petrov                          # новый пароль
```

Роль — это должность по штатному расписанию, а не набор галочек:

| Ключ | Должность | Права |
|---|---|---|
| `owner` | Создатель системы | все; отключить и разжаловать нельзя |
| `head` | Начальник отдела | администратор |
| `deputy` | Заместитель начальника отдела | администратор |
| `lead` | Начальник группы | администратор |
| `senior` | Старший инженер отдела | письма, отчёты, библиотека |
| `engineer` | Инженер отдела | письма, отчёты, библиотека |
| `guest` | Гость | только помощник; переписка не сохраняется, личного кабинета нет |

Письма и отчёты ведут все должности: делить отдел на «пишущих» и «читающих»
незачем, в жизни такого деления нет. Права администратора — военнослужащие, удаление
документов, журнал действий — у первых четырёх, до начальника группы
включительно. Менять чужую запись можно только военнослужащему младше себя по
должности: заместитель не разжалует начальника отдела, а создателя системы не
тронет никто. У военнослужащего есть ещё группа (`-Team`) и, если нужно,
подразделение по штату (`-Department`): группа подписана рядом с человеком в
нагрузке в сводке. Отдел у всех один — тот, что стоит в настройках
(`brand_name`), — и у каждого его не спрашивают; `-Department` заполняют
только тем, кто по штату числится в другом подразделении.

То же самое есть в веб-интерфейсе, в разделе «Военнослужащие». `users.ps1` — обёртка
над командой `reportgen`, при желании её можно звать напрямую:

```powershell
reportgen useradd --login admin --role owner --name "Петров П. П." `
                  --team "1 группа"
```

## Шаг 6. RFC: архив описаний протоколов

RFC — то место, где написано, какие поля в кадре и что в них лежит. Когда
инженер разбирает дамп мультиплексора или непонятный заголовок, ответ обычно
там. Без них система будет пересказывать книги вместо того, чтобы назвать
поле.

**На машине с интернетом:**

```powershell
cd reportgen\scripts\offline
powershell -ExecutionPolicy Bypass -File .\rfc.ps1 -Probe
powershell -ExecutionPolicy Bypass -File .\rfc.ps1 -Destination D:\rfc
```

Около 9800 документов, ~450 МБ, полтора-два часа (между запросами пауза, чтобы
не выглядеть атакой на сервер, который раздаёт всё это бесплатно). Прервалось —
запустите снова, уже скачанное не перекачивается.

Итог в конце: «номеров без текста» — это нормально, часть номеров никогда не
публиковалась. А «не скачано из-за ошибок связи» — повод запустить ещё раз.

Нужны не все, а конкретные:

```powershell
.\rfc.ps1 -Only 791,793,1122,2616,7230 -Destination D:\rfc
```

Адрес закрыт корпоративным шлюзом — возьмите зеркало IETF:

```powershell
.\rfc.ps1 -BaseUrl https://www.ietf.org -Destination D:\rfc
```

**Перенести:** скопируйте `D:\rfc\standards\rfc` в
`C:\reportgen\data\library\standards\rfc` на рабочей машине. Дальше — обычная
загрузка библиотеки (шаг 7).

Названия, годы и разделы разберутся сами. Отменённые редакции (RFC 2616,
заменённый на 7230) пометятся заменёнными и в поиск не попадут — иначе
система с равной охотой сослалась бы и на действующий документ, и на
отменённый.

## Шаг 7. Загрузить библиотеку

Положите документы в `C:\reportgen\data\library` и выполните:

```powershell
cd C:\reportgen\app\scripts\windows
.\load-library.ps1
```

Скрипт проверит установку, покажет, какие форматы читаются на этой машине,
разберёт документы, построит векторы и напечатает итог.

**Раскладывать по папкам не обязательно.** Принесли папкой «Разное» или
выгрузкой со старого сервера — кладите как есть: тип определится по самому
документу («настоящий стандарт распространяется» — стандарт, `absolute maximum
ratings` — паспорт, «УТВЕРЖДАЮ» — регламент). Не опознано — полка «Прочее», где
документ видно и он ждёт разбора. Если вы всё же разложили по папкам —
папка главнее, спорить система не будет.

Полезные ключи:

```powershell
.\load-library.ps1 -Jobs 12                      # больше потоков — быстрее
.\load-library.ps1 -Path D:\новые -DocType standards
.\load-library.ps1 -Force                        # перечитать всё заново
```

`-Jobs` заметно ускоряет сканы: на 16 потоках PDF на 300 МБ обрабатывается не
за два часа, а за считанные минуты. Ставьте по числу ядер.

Что читается — 34 конвертера на 56 расширений, от PDF и DOCX до DjVu, `.mht`,
чертежей `.odg` и архивов: [docs/17-formats.md](17-formats.md).
Как устроены полки и направления: [docs/18-library.md](18-library.md).

## Шаг 8. Работа

Подробная инструкция для инженера — [docs/19-guide.md](19-guide.md). Коротко:

* **Письмо.** Единица работы — письмо: входящее письмо и
  подготовленный на него ответ. В карточке — входящий номер, дата письма, срок
  ответа, приоритет (обычный, важный, срочный), исполнитель и примечание.
  Состояния: принято, в работе, на проверке, отправлено, в архиве.
* **Сводка.** Что в отделе сегодня: письма в работе, просроченные и те, у
  которых срок наступает в ближайшие три дня, письма без исполнителя, личный
  состав и нагрузка по людям, дежурство и отсутствия, движение за период.
  Дежурство и отсутствия (отпуск, больничный, командировка, учёба) отмечают
  там же; это делают должности с правами администратора.
* **Вопрос-ответ.** Спросите как коллегу: «какие поля в заголовке HDLC и что
  означает бит P/F». Ответ придёт со ссылками на конкретные документы и
  страницы — ссылки проверяемые, по ним можно открыть сам исходный файл.
  К вопросу можно приложить файл: дамп, лог, снимок экрана или документ.
  Двоичный `.pcap` разобрать нечем — сделайте в Wireshark текстовый экспорт
  («Файл» → «Экспортировать пакеты» → «Как обычный текст») и приложите его.
* **Отчёт.** Числа берутся из факт-пакета, модель пишет только текст. Перед
  утверждением работает верификатор: если в тексте появилось число, которого
  нет в факт-пакете, отчёт не утвердить. Это не придирка — так ловится
  единственная ошибка, которую человек в готовом отчёте не замечает.
* **Правки.** Исправления инженера уходят в датасет: со временем модель пишет
  ближе к тому, как принято у вас.

> **О словах и названиях.** В интерфейсе и в документации — «письмо». В базе
> данных таблица и в API маршруты по-прежнему называются `cases`: переименовать
> их на работающей установке дороже, чем один раз объяснить расхождение. Если
> читаете журнал действий, разбираете резервную копию или дёргаете
> `GET /api/cases` — это про письма.

Резервная копия: `.\backup.ps1` (база, настройки, отчёты; хранит 14 последних).

## Шаг 9. Обновление кода

Обновление — это только исходники, несколько мегабайт: модели и программы
заново не нужны.

**На машине с интернетом:**

```powershell
cd reportgen
git pull
git bundle create D:\reportgen-update.bundle --all
```

**На рабочей машине** (перенесите файл `.bundle`):

```powershell
cd C:\reportgen\app
git pull D:\reportgen-update.bundle
.\scripts\windows\stop-all.ps1
.\scripts\windows\start-all.ps1
```

База приводится в порядок сама при первом запуске: недостающие колонки
добавляются, а прежние роли переводятся в должности. Первый заведённый
администратор (служебная запись `local` не в счёт — под ней нельзя войти)
становится создателем системы, остальные `admin` — начальниками отдела,
`viewer` — инженерами отдела. Прав при этом никто не теряет: на изолированной
машине некому будет разбираться, почему после обновления перестал открываться
раздел «Военнослужащие». Кто кем стал, покажет `.\users.ps1`.

Там же чинится номер группы. Одно время это поле проверялось как число, и
обновление стирало из него всё, что числом не было. Проверку сняли: формат
задаёт делопроизводство отдела, а не программа — пишут и «1274», и «12/345»,
и «в/ч 74326», и словами. Если стирание успело отработать, обновление
возвращает написанное обратно из примечания к письму.

Если обновление меняло разбор документов, перечитайте библиотеку:
`.\load-library.ps1 -Force -Jobs 12`.

## Шаг 10. Если что-то пошло не так

| Что видно | В чём дело | Что делать |
|---|---|---|
| `pack.ps1 -Probe`: «недоступно источников: N» | адрес сменился или закрыт шлюзом | В выводе указано, какой именно источник. Скачайте файл руками и положите в комплект — `verify.ps1` подтвердит |
| `verify.ps1`: «ПОВРЕЖДЁН» | сбой при копировании | Перенесите эти файлы заново. Ставить с повреждённым комплектом нельзя |
| Установка кончилась замечаниями | часть шагов не прошла | Замечания перечислены поимённо. Установка при этом рабочая — доделайте названное |
| `llama-server.exe не найден` | в комплект попал не тот архив llama.cpp | `pack.ps1 -Only llama` на машине с интернетом, перенести каталог `llama\` |
| Модель отвечает очень медленно | драйвер ушёл в оперативную память | Отключите резервную системную память CUDA (шаг 4) |
| Помощник отвечает без ссылок на документы | промпт не влез в окно контекста, начало отброшено | Верните `-Context 32768` и `assistant_context_chars` = 26000 (шаг 5) |
| Порт занят | комплекс уже запущен | `.\stop-all.ps1`, затем `.\start-all.ps1` |
| Документ не прочитался | формата нет или файл битый | `reportgen formats` покажет, что читается на этой машине; в карточке документа написано, что именно не получилось |
| Русский текст «оБУФПСЭЙК» | старая кодировка | Так больше не бывает: кодировка определяется по содержимому. Если увидели — сообщите, это ошибка |

Остальное — по документам: [11-windows.md](11-windows.md) (Windows и
видеокарта), [15-offline.md](15-offline.md) (комплект и перенос),
[07-security-and-ops.md](07-security-and-ops.md) (эксплуатация),
[16-quality.md](16-quality.md) (как проверять качество ответов).

## Приложение. Все команды одним списком

**Машина с интернетом:**

```powershell
git clone <адрес> reportgen
cd reportgen\scripts\offline
.\pack.ps1 -Probe                                  # проверить адреса
.\pack.ps1 -Destination D:\reportgen-offline       # собрать комплект (~19 ГБ)
.\rfc.ps1 -Probe                                   # проверить источник RFC
.\rfc.ps1 -Destination D:\rfc                      # скачать RFC (~450 МБ)
git bundle create D:\reportgen-update.bundle --all # для будущих обновлений
```

**Рабочая машина:**

```powershell
cd C:\install\reportgen-offline
.\verify.ps1                                       # проверить комплект
.\install-offline.ps1                              # установить (от администратора)

cd C:\reportgen\app\scripts\windows
.\00-check.ps1                                     # проверить машину
.\start-all.ps1                                    # запустить
.\users.ps1 -Add admin -Role owner -Name "Петров П. П."      # создатель системы
```
