# 21. Анализатор сетевых пакетов

Страница **«Пакеты»** (меню «Знание») — разбор сетевого захвата по уровням на
сервере отдела, без интернета и без установки программ на рабочие места:
открывается в браузере, как всё рабочее место.

## 21.1. Откуда берутся пакеты

- **Файл захвата**: pcap (микро- и наносекундный, оба порядка байт), pcapng
  (блоки SHB/IDB/EPB/SPB, разрешение времени интерфейса), `.sig` (кадры с
  двухбайтовой длиной — разметка определяется сама).
- **Из разбора потока**: у этапа, после которого получились пакеты IP или
  кадры, — кнопка **«Пакеты»**. Кадры без канального заголовка (после HDLC,
  из .sig) разбираются «по признакам»: IP по контрольной сумме заголовка,
  PPP по `FF 03`, Cisco HDLC, Ethernet по типу, затем канальные протоколы по
  признакам их стандартов — Frame Relay (адрес Q.922 и NLPID, LMI), LAPD
  (EA, SAPI 0/1/16/62/63, кадры I/S/U Q.921), LAPB без байта направления
  (адрес A/B/C/D, пакет X.25), AX.25 (позывные), MTP2 (LI сходится с длиной).
  Если разбор потока опознал канальный протокол по всей массе кадров, этап
  выгружается pcap с типом канала (MTP2 — 140, LAPD — 203, Frame Relay — 107,
  AX.25 — 3) и открывается сразу нужным разборщиком.

Разбор идёт в фоне; страница показывает, сколько пакетов разобрано. Захваты
хранятся (последние 30) и видны только тому, кто их открыл; в резервную
копию они не идут — пересчитываются из файла.

## 21.2. Что видно

- **Список пакетов**: номер, время от начала, источник, получатель, протокол,
  длина, сведения. Строка окрашена по семейству протокола (TCP, UDP, DNS,
  HTTP, TLS, ARP, ICMP, маршрутизация); ошибки — красным со знаком ⚠. Цвет
  дублирует столбец «Протокол» — он не единственный признак. ↑/↓ — по списку.
- **Дерево полей** — слева, с самого верха: уровни снизу вверх, у каждого
  поля — значение и место в байтах `[34…35]`. Всё прочее о пакете — справа
  от дерева: заголовок с действиями («Следовать за потоком», «Разбирать порт
  как…», «Спросить помощника о пакете»), ошибки, вид байт и дамп. Щелчок по
  полю подсвечивает его байты в дампе; наведение на байт дампа подсвечивает
  поле, из которого он прочитан. Над дампом — готовое выражение фильтра для
  выбранного поля: **«Отобрать такие»**, **«Кроме таких»**.
- **Описание — справа.** Пояснения к разделу и вкладкам (матрица байт,
  протоколы, неизвестные форматы) — в правой панели «Описание», свёрнутой по
  умолчанию; открывается щелчком по ручке у правого края.
- **Дамп байт**: HEX, DEC, BIN или ТЕКСТ (CP1251 для кириллицы), порядок бит
  в байте — старший или младший первым.
- **Контрольные суммы** пересчитываются: IPv4 (заголовок), TCP/UDP (с
  псевдозаголовком IPv4/IPv6), ICMP, ICMPv6, SCTP (CRC32c). Неверная —
  красным и в списке ошибок. У TCP «не сошлась» бывает и у исправного пакета:
  захват на передающем узле до подсчёта суммы сетевой картой — так и написано.
- **Фрагменты IPv4 собираются**: к последнему фрагменту добавлен разбор
  собранного пакета и его собственный дамп.

## 21.3. Фильтр

Язык в духе Wireshark, но свой и безопасный:

| Выражение | Что отбирает |
|---|---|
| `tcp`, `dns`, `arp`, `ip`, `vlan` | пакеты с этим уровнем |
| `ip.addr == 10.0.0.0/8` | адрес (любой из двух) в подсети |
| `ip.src == 10.1.1.1`, `ipv6.dst == 2001:db8::1` | источник, получатель |
| `tcp.port == 443 or udp.port == 53` | порты |
| `port in {53 123 161}` | порт TCP, UDP или SCTP из списка |
| `dns.qry.name contains "mail"` | подстрока без учёта регистра |
| `http.host matches "^mail\."` | регулярное выражение |
| `frame.len > 1000 and not arp` | длина, логика `and`/`or`/`not`, скобки |
| `http.request.method == "POST"` | любое поле из дерева (ключ — в подсказке поля) |
| `frame[12:2] == 0800` | байты 12–13 кадра (HEX: `0800`, `08:00`, `0x0800`; десятичное — `2048`) |
| `payload[0].hi == 0xA`, `payload[0].lo == 5` | полубайты первого байта нагрузки верхнего уровня |
| `frame contains ff:d8:ff`, `payload contains "JFIF"` | последовательность байт или текст |
| `expert` (или `ошибки`) | пакеты с ошибками (суммы, обрывы) |
| `данные` (или `data`) | нагрузка, которую ни один разборщик не взял |

Статистика на всех вкладках считается по отобранным пакетам.

Ошибка в выражении видна по мере набора — поле краснеет, под ним сказано,
что не так, ещё до «Отобрать». Применённые фильтры запоминаются в этом
браузере (последние 20) и предлагаются при наборе. Клавиши: **/** — к
фильтру, **Esc** — вернуть применённый; в списке пакетов **↑/↓**,
**PageUp/PageDown** (по 20), **Home/End**.

## 21.3а. Разбирать как

Служба на нестандартном порту (HTTP на 8888, DNS на 5000, свой SIP) по
таблице портов не узнаётся. Кнопка **«Разбирать как…»** в шапке захвата
или **«Разбирать порт N как…»** у пакета задаёт правило «UDP/TCP порт →
разборщик»; захват разбирается заново в фоне, фильтры и статистика видят
новый разбор. Разборщик и по выбору аналитика проверяет, что данные его: не
подошли — это видно в ошибках пакета («разбирать как BGP (порт 8888): данные
не подошли»), и разбор идёт дальше обычным путём. «Не разбирать (данные)» —
когда угадывание по содержимому ошибается. Правило снимается крестиком.

## 21.4. Вкладки

- **Обзор** — главное одним взглядом, считается само: пакеты, объём,
  длительность, средняя скорость, пакеты с ошибками, файлы в потоках;
  протоколы с долями, главные диалоги IP, имена DNS, серверы TLS (SNI), узлы
  HTTP, виды ошибок, неразобранная нагрузка по портам. Блок **«На что
  посмотреть»** — приметы с кнопкой отбора: протоколы открытым текстом (HTTP,
  FTP, Telnet, POP3, IMAP, SMTP, SNMP, TFTP, Syslog), DNS-запросы без ответа
  (сопоставление по идентификатору и порту клиента), суммы TCP, не сошедшиеся
  у большинства пакетов (захват на передающем узле, а не порча), больше всего
  неразобранного, найденные файлы. Любая строка обзора — щелчок: отбор пакетов
  или переход на нужную вкладку.
- **Протоколы** — иерархия протоколов: сверху схема-«сосулька» (ширина — доля
  пакетов или байт внутри узла, ряд — уровень вложенности; двойной щелчок —
  приблизить узел, «хлебные крошки» — назад), ниже дерево (раскрытие, поиск
  протокола, полоса доли, клавиши ↑ ↓ ← → и Enter) и карточка узла: пакеты,
  байты, средний размер, доля от всего и от родителя, что внутри и сколько
  пакетов кончаются на этом уровне; кнопки «Показать пакеты», «Исключить»,
  «И к фильтру», «Приблизить на схеме». Цвет — уровень протокола (канальный,
  сетевой, транспортный, прикладной), рядом всегда подпись.
- **Диалоги** — Ethernet, IP, TCP, UDP: пакеты и байты в каждую сторону,
  начало, длительность, протоколы; щелчок — отбор пакетов диалога.
- **Узлы** — адреса: отправлено, получено, службы (порты < 1024).
- **Матрица байт** — пакеты строками, байты столбцами, выравнивание от начала
  кадра или от нагрузки верхнего уровня, окно по 16–256 столбцов. Над
  столбцами — **профиль энтропии**: низкие столбики — постоянные поля, типы,
  синхрослова; высокие — данные. Щелчок по заголовку — **статистика столбца**
  (или поля 2–8 байт): значения по частоте (щелчок — отбор), энтропия,
  различных значений, полубайты, доля единиц по битам и вывод: «постоянное
  поле», «счётчик +1», «растёт с шагом», «поле длины: длина пакета − k»,
  «поле типа», «похоже на случайные данные». **Правая кнопка** на ячейке —
  отбор по байту, полубайту, полю, «кроме», статистика; на заголовке —
  статистика, начать матрицу с этого байта. Вид — HEX/DEC/BIN/ТЕКСТ, порядок бит.
- **Время** — пакеты или байты за интервал (одна величина за раз), с таблицей.
- **DNS** — запросы и ответы: клиент, сервер, имя, тип, ответы, код.
- **HTTP** — запросы с ответами: метод, узел, адрес, код, агент.
- **TLS** — ClientHello: имя сервера (SNI), ALPN, версии.
- **Файлы в потоках** — потоки TCP/UDP собираются по направлениям (у TCP —
  по номерам последовательности, без повторов), в собранных байтах ищутся
  файлы по сигнатуре со сверкой структуры (JPEG, PNG, GIF, PDF, ZIP/DOCX,
  7z, gzip, ELF, PE и др.): поток, смещение, длина, пакет, с которого файл
  начинается, и кнопка **«Скачать»**. Файл, переданный по HTTP, FTP или
  своим протоколом, виден сразу — не нужно искать его вручную по пакетам.
- **Ошибки** — по видам, с номерами пакетов.
- **Неизвестные форматы** — нагрузка без известного разборщика по группам
  (транспорт и порт службы): поля неизвестного формата (постоянные, счётчики,
  длины, типы) и CRC вслепую — тот же анализ, что у кадров потока.

**Следовать за потоком** (у пакета TCP/UDP/SCTP): нагрузки в обе стороны по
порядку, у TCP — по номерам последовательности, повторы и перекрытия
отбрасываются; текстом или HEX; кнопка отбирает пакеты потока.

**Выгрузка**: отбор — в pcap (открывается любой программой) или таблицей CSV.
**Спросить помощника** — о захвате (иерархия, диалоги, ошибки) или о пакете
(всё дерево полей с местами в байтах): помощник объясняет по RFC и стандартам
из библиотеки.

**VRRP** — версии 2 (RFC 3768: проверка подлинности, интервал, данные
подлинности) и 3 (RFC 5798: наибольший интервал в сотых секунды; поверх IPv6
— адреса по 16 байт). Контрольная сумма сверяется: у версии 2 — по
сообщению, у версии 3 — с псевдозаголовком IP; часть реализаций VRRPv3 поверх
IPv4 считает её без псевдозаголовка — сверяются оба способа, и в поле сказано,
какой сошёлся.

**Группы протоколов по стандартам.** Сверх базового набора разборщики
собраны по группам (`setevoy/protokoly/`); каждый модуль сам регистрирует
себя в таблицах разбора — по EtherType, номеру протокола IP, LLC, PPP,
PPID и порту SCTP, портам TCP/UDP, типу канала pcap и признакам. Структуры
полей — строго по документам, перечисленным в модуле (раздел стандарта у
каждого разборщика); таблицы кодов — только общеизвестные значения,
незнакомое показывается числом.

только опознаётся.

Разборщик протокола проверяет, что данные его (длины сходятся, значения в
пределах): номер порта один протокола не делает. RTP по одному пакету не
доказать — он опознаётся только по строгим признакам и помечен «по признакам».
Таблицы значений держатся короткими — только общеизвестные коды; имена наборов
шифров TLS не подставляются (показываются коды): таблица IANA здесь не
хранится и по памяти не пишется.

## 21.6. Скорость

Захват до 200 000 пакетов. Разбор — в фоне; сводки и поля для фильтров
хранятся на диске, подробный разбор пакета строится заново по щелчку (доли
миллисекунды). Разобранный захват держится в памяти (два последних), фильтр
запоминается — повторный отбор и статистика мгновенны.
