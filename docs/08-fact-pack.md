# 08. Формат факт-пакета

Факт-пакет — контракт между слоем автоанализа (кто считает) и слоем генерации
(кто пишет). Его стоит зафиксировать до начала разработки: он один определяет,
какие числа вообще могут появиться в отчёте.

Реализация и валидация — `src/reportgen/facts.py`, пример —
`examples/cases/case-2024-118.json`.

## Верхний уровень

| Поле | Обяз. | Назначение |
|---|---|---|
| `case_id` | да | Идентификатор обращения; попадает в шапку отчёта |
| `report_type` | да | Тип отчёта; должен совпадать с `report_type` шаблона-плана |
| `group_no` | нет | Номер группы, откуда пришло письмо (любой текст) |
| `request` | нет | Формулировка обращения своими словами |
| `equipment` | нет | Словарь «что за оборудование»: линия, модем, модуляция |
| `keywords` | нет | Ключевые слова; используются как подсказки поиску по литературе |
| `artifacts` | нет | Список полученных материалов: `name`, `type`, `sha256`, `note` |
| `measurements` | нет | Словарь измерений (см. ниже) — основной массив чисел |
| `findings` | нет | Список находок анализатора |
| `timeline` | нет | Хронология работ: `date`, `event` |
| `registrations` | нет | Опись регистраций — список записей, по которому шаблон разворачивает раздел на каждую (см. ниже) |

## Опись регистраций (`registrations[]`)

Список произвольных записей: имя списка знает шаблон (`repeat_over`), а не
код. Поля записи выбирает шаблон же — обязательные перечислены в
`item_required`, остальные пишутся по надобности и попадают в раздел
дословно, вместе с русскими подписями из `fact_titles`.

```json
{
  "caption": "Файлы в каталогах «7419_8931_CQPSK_H», «7419_8931_CQPSK_V»",
  "catalogs": "7419_8931_CQPSK_H, 7419_8931_CQPSK_V",
  "line_type": "РРЛС",
  "modulation": "ФМ-4С",
  "clock_khz": 8931,
  "record_format": "оцифрованный участок спектра",
  "equipment": "Ericsson MiniLink (Швеция)",
  "frame_bits": 1116,
  "scrambler": "АС (17,3)"
}
```

Порядок записей — порядок разделов в готовом письме, поэтому менять его
случайно нельзя: в приложении для этого есть стрелки, а не перетаскивание.
Числа из записи проверяются так же строго, как измерения: параметры кодов
и скремблеров разбираются по элементам, и «RS (204,188,12)» — это 204, 188
и 12, а не одно число.

## Измерение (`measurements[<ключ>]`)

| Поле | Обяз. | Назначение |
|---|---|---|
| `value` | да | Значение. Число — предпочтительно; строка — только для нечисловых величин |
| `title` | нет | Человеческое название; попадает в таблицы отчёта |
| `unit` | нет | Единица измерения. Заполняйте всегда, где она есть |
| `method` | нет | Как получено — «метод 99 % мощности, усреднение по 64 сегментам» |
| `uncertainty` | нет | Погрешность. Отсутствие погрешности в техотчёте — замечание к отчёту |
| `source` | нет | Артефакт или инструмент, откуда значение |
| `note` | нет | Оговорки: условия применимости, известные ограничения |

Ключ измерения (`snr`, `evm`, `occupied_bandwidth`) — это то, чем оперируют
шаблоны в `required_facts`. **Заведите общий словарь ключей на всю компанию**:
если один анализатор пишет `snr`, а другой `SNR_db`, шаблоны перестанут
работать, а инженер этого не заметит — отчёт просто будет тише, чем нужно.

## Находка (`findings[]`)

| Поле | Обяз. | Назначение |
|---|---|---|
| `id` | да | Короткий идентификатор (`F1`, `F2`) |
| `severity` | да | Один из `info`, `low`, `medium`, `high`, `critical` |
| `title` | да | Формулировка одной строкой |
| `description` | нет | Уточнение: что именно наблюдается |
| `evidence` | нет | Ключи измерений, подтверждающих находку. Проверяется при загрузке |
| `refs` | нет | Ссылки на нормативные документы и разделы |

`severity` управляет содержанием отчёта: секции шаблона объявляют
`findings_min_severity`, и в «Выводы» попадают только находки нужного уровня.
Порог назначает анализатор, а не модель.

## Правила, которые стоит соблюдать при формировании

1. **Ни одного числа мимо факт-пакета.** Если инженер добавил наблюдение
   руками — оно должно попасть в факт-пакет, а не сразу в текст.
2. **Единицы отдельно от значения.** `{"value": 13.7, "unit": "дБ"}`, не
   `{"value": "13.7 дБ"}`: иначе невозможен ни пересчёт, ни сравнение с нормой.
3. **Погрешность там, где она есть.** Отсутствие погрешности — тоже сведение,
   его лучше указать явно в `note`.
4. **Никаких выводов в измерениях.** «Уровень превышает норму» — это находка,
   а не измерение.
5. **Факт-пакет версионируется и хешируется** (`FactPack.digest()`): хеш
   попадает в служебный блок отчёта, чтобы отчёт можно было воспроизвести.
6. **Анонимизация — на входе.** Названия организаций заменяются на
   идентификаторы до того, как что-либо попадёт в конвейер (док. 07).
