# 15. Перенос в офлайн: собрать на одной машине, установить на другой

Система рассчитана на изолированный контур. Задача этого документа — чтобы
установка на машине без интернета прошла с первого раза, а не превратилась в
неделю выяснения, какого файла не хватает.

Схема: на машине **с интернетом** собирается комплект (один каталог), он
переносится на внешнем диске, на машине **без интернета** проверяется и
разворачивается. В процессе установки не скачивается ничего — если чего-то не
хватает, установщик говорит, чего именно, и продолжает с тем, что есть.

**Всё качается автоматически.** Установщики LibreOffice, Tesseract, DjVuLibre,
7-Zip, Git, Visual C++ Redistributable и Python сборщик находит и скачивает
сам: у каждой программы задан список источников, и он пробует их по порядку.
Руками ничего искать не нужно.

## 15.0. Коротко: три команды

На машине с интернетом:

```powershell
git clone <адрес-репозитория> reportgen
cd reportgen\scripts\offline
powershell -ExecutionPolicy Bypass -File .\pack.ps1 -Probe                     # 1. проверить адреса, полминуты
powershell -ExecutionPolicy Bypass -File .\pack.ps1 -Destination D:\reportgen-offline   # 2. собрать, несколько часов
```

Перенести каталог на диск. На офлайн-машине:

```powershell
cd C:\install\reportgen-offline
.\verify.ps1                       # 3. проверить, что доехало целым
.\install-offline.ps1              # 4. установить
```

Остальное в этом документе — подробности и что делать, когда что-то пошло не так.

## 15.1. Что попадает в комплект

| Каталог | Размер | Что внутри |
|---|---|---|
| `models/` | ~17 ГБ | Основная модель, запасная поменьше, эмбеддер, реранкер |
| `llama/` | ~1 ГБ | Сборка llama.cpp под CUDA, библиотеки CUDA, предыдущий выпуск про запас |
| `tools/` | ~510 МБ | LibreOffice, Tesseract, DjVuLibre, 7-Zip, Git, VC++ Redistributable, Python |
| `tessdata/` | ~50 МБ | Русский и английский для Tesseract, точный и быстрый варианты |
| `wheels/` | 60–120 МБ | Пакеты Python, ставятся без сети (`pip --no-index`) |
| `code/` | ~5 МБ | Исходники плюс git-бандл: из него разворачивается репозиторий с историей |
| `docs/` | ~1 МБ | Вся документация, читается без разворачивания комплекта |
| `manifest.json` | — | SHA-256 каждого файла и каталог «что откуда скачано» |

Итого около **19 ГБ**. Нужен внешний диск или флешка от 32 ГБ.

**Комплект не архивируется.** Модели GGUF уже сжаты, а архив на двадцать
гигабайт добавляет только риска: одна ошибка чтения — и не распаковать ничего.
Каталог копируется как есть, а целостность проверяется по манифесту.

### Зачем в комплекте вещи «про запас»

| Что | Зачем |
|---|---|
| Вторая модель поменьше (Qwen3-8B вместо 14B) | Если основная не влезет в видеопамять вместе с эмбеддером и реранкером — на изолированной машине скачать другую будет неоткуда |
| Предыдущий выпуск llama.cpp | Свежая сборка иногда не заводится на конкретном драйвере; это единственный способ проверить, дело в ней или нет |
| Git for Windows | Без него обновления придётся возить копированием файлов, теряя историю и возможность откатиться |
| Оба варианта языковых файлов Tesseract | `best` точнее на плохих сканах, `fast` втрое быстрее; какой лучше на вашей литературе, видно только на месте |
| Visual C++ Redistributable | На свежеустановленной Windows его часто нет, а без него не запускается llama.cpp |

## 15.2. Главное правило: колёса собираются на такой же системе

Пакеты Python зависят от операционной системы и версии интерпретатора. Колёса,
скачанные на Linux, **не подойдут** для Windows, а собранные для Python 3.11 не
встанут на 3.12.

- Целевая машина Windows → собирайте комплект **на Windows** с той же версией
  Python (`pack.ps1`).
- Целевая машина Linux → собирайте на Linux, желательно того же дистрибутива
  (`pack.sh`).

Установщик это проверяет: в комплекте лежит `wheels/PYTHON-VERSION.txt`, и при
несовпадении установка останавливается с внятным сообщением, а не падает
посреди процесса.

> Скачать колёса под Windows с Linux-машины (`pip download --platform win_amd64`)
> технически можно, но `uvicorn[standard]` тянет `uvloop`, которого под Windows
> нет, и сборщик зависимостей заходит в тупик. Если другого выхода нет, качайте
> без `[standard]`: `fastapi uvicorn httptools websockets python-docx pymupdf
> numpy python-multipart itsdangerous jinja2` — этого достаточно, uvicorn просто
> будет работать на стандартном цикле событий, чуть медленнее.

Всё остальное — программы, модели, llama.cpp — от системы сборки не зависит:
сборщик всегда качает файлы для Windows, даже если запущен из WSL.

## 15.3. Шаг 1. Проверка адресов (полминуты)

Сначала — короткая проверка, что все адреса живы. Она не качает ничего, только
спрашивает у каждого источника, отдаст ли он файл:

```powershell
cd reportgen\scripts\offline
powershell -ExecutionPolicy Bypass -File .\pack.ps1 -Probe
```

Вывод — таблица: что, какой файл, из какого источника, и ответ сервера.

```
Что         Файл                                       Источник                          Ответ
---         ----                                       --------                          -----
libreoffice LibreOffice_25.8.2_Win_x86-64.msi          documentfoundation.org 25.8.2     OK 206
tesseract   tesseract-ocr-w64-setup-5.5.3.20260724.exe SourceForge/tesseract-ocr.mirror  OK 206
djvulibre   DjVuLibre-3.5.29_DjView-4.12_Setup.exe     SourceForge/djvu                  OK 206
sevenzip    7z2601-x64.exe                             SourceForge/sevenzip              OK 206
tessdata    best/rus.traineddata                       GitHub/tesseract-ocr/tessdata_best OK 206
llm         Qwen3-14B-Q5_K_M.gguf                      huggingface/Qwen/Qwen3-14B-GGUF   OK 206
```

Если какая-то строка красная — поправьте адрес в `bundle.example.json` или
скачайте этот файл руками в каталог `tools`. Узнать это за тридцать секунд
гораздо приятнее, чем через четыре часа закачки.

## 15.4. Шаг 2. Сборка

```powershell
# при необходимости поправьте, какие модели качать
notepad bundle.example.json

powershell -ExecutionPolicy Bypass -File .\pack.ps1 -Destination D:\reportgen-offline
```

Скрипт скачает всё, сверит контрольные суммы там, где источник их даёт,
посчитает SHA-256 каждого файла и напишет манифест. Скачивание идёт через
`curl` с докачкой: если связь оборвалась, просто запустите `pack.ps1` снова —
уже скачанное не перекачивается.

Ключи:

| Ключ | Зачем |
|---|---|
| `-Probe` | Только проверить адреса, ничего не качать |
| `-Destination <путь>` | Куда складывать комплект |
| `-Config <файл>` | Другой файл настроек вместо `bundle.example.json` |
| `-Only llm,tesseract` | Скачать только перечисленное (например, добрать то, что не докачалось) |
| `-Skip llm-fallback,git` | Пропустить перечисленное |
| `-SkipModels`, `-SkipWheels`, `-SkipLlama`, `-SkipTools` | Пропустить целый раздел |

Сразу после сборки проверьте комплект на месте — до того, как копировать его на
диск:

```powershell
cd D:\reportgen-offline
.\verify.ps1
```

## 15.5. Шаг 3. Перенос

Скопируйте каталог `reportgen-offline` целиком. Не архивируйте.

Файловая система на диске должна быть **NTFS или exFAT**. На FAT32 предел
размера файла 4 ГБ, а модель весит больше — копирование оборвётся на середине.

## 15.6. Шаг 4. Установка на офлайн-машине

**PowerShell нужно запустить от имени администратора.** Без этого не встанут
LibreOffice, Tesseract и DjVuLibre, а языковые файлы не скопируются в
Program Files; установщик это проверяет и сразу останавливается.

```powershell
# скопируйте каталог с диска на локальный диск, например в C:\install\reportgen-offline
cd C:\install\reportgen-offline

Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
.\verify.ps1                       # проверка после переноса — обязательно
.\install-offline.ps1              # установка в C:\reportgen
```

Свободного места на целевом диске нужно примерно в полтора раза больше объёма
комплекта — около 27 ГБ при комплекте в 19 ГБ: модели копируются, а архивы
llama.cpp ещё и распаковываются. Установщик считает это сам и останавливается
заранее, а не на середине копирования.

Что делает установщик:

1. Проверяет права администратора и свободное место.
2. Сверяет контрольные суммы. Двадцать гигабайт через флешку регулярно
   приезжают с одним битым файлом; узнать об этом лучше до установки.
3. Проверяет наличие и версию Python, при отсутствии ставит его из комплекта
   (тихо, с добавлением в PATH) и просит перезапустить окно.
4. Тихо ставит LibreOffice, Tesseract, DjVuLibre, 7-Zip, Git и VC++
   Redistributable — то, чего ещё нет на машине, — и **докладывает русский
   язык в Tesseract**, проверяя `tesseract --list-langs`.
5. Разворачивает код в `C:\reportgen\app`. Git к этому моменту уже установлен,
   поэтому код **клонируется из git-бандла**, и обновления потом ставятся
   одной командой `git pull`.
6. Распаковывает llama.cpp, раскладывает модели, откладывает запасной выпуск.
7. Ставит зависимости **только из локальных колёс** — pip в сеть не ходит.
8. Создаёт `settings.json`, показывает список доступных форматов и заводит
   создателя системы — учётную запись с должностью `owner` и полными правами.

Порядок здесь не случаен: программы ставятся до разворачивания кода, потому
что Git из комплекта нужен уже на шаге 5, а PATH текущего окна после тихой
установки не обновляется сам — установщик перечитывает его из реестра.

Ключи: `-Target D:\reportgen` (другой каталог), `-SkipTools` (не ставить внешние
программы), `-Unattended` (не задавать вопросов; создатель системы при этом не
заводится — сделайте это потом командой `users.ps1 -Add`), `-SkipVerify` (не
сверять контрольные суммы — не стоит).

В конце установщик показывает список замечаний: всё, что не встало или встало
не полностью. Пустой список — установка прошла чисто.

### Почему русский язык докладывается отдельно

Тихая установка Tesseract (`/S`) ставит только языки по умолчанию, русского
среди них нет. Поэтому файлы `rus.traineddata` лежат в комплекте отдельно и
копируются в `C:\Program Files\Tesseract-OCR\tessdata` уже после установки, а
затем установщик проверяет `tesseract --list-langs`. Без этого сканы русских
книг распознавались бы в бессмыслицу — а это большая часть технической
литературы в DjVu.

В комплекте два набора: `best` (точнее, ~15 МБ на язык) и `fast` (втрое
быстрее, ~4 МБ). По умолчанию ставится `best`. Если распознавание тысяч страниц
идёт слишком долго — скопируйте файлы из `tessdata\fast` поверх.

## 15.7. Шаг 5. Запуск

```powershell
cd C:\reportgen\app\scripts\windows
.\00-check.ps1        # проверка машины
.\start-all.ps1       # запуск модели, эмбеддера, реранкера и интерфейса
```

Перед первым запуском обязательно отключите резервную системную память CUDA в
панели NVIDIA — иначе модель «влезет» в память с запасом за счёт оперативной и
будет работать в разы медленнее. Как именно — в
[docs/11-windows.md](11-windows.md), шаг 0.

Модель поднимается с контекстом 32768 токенов на два слота, то есть 16384 на
разговор: столько нужно помощнику, чтобы уложить найденный материал и оставить
место под ответ. Если видеопамяти не хватает, контекст снижают ступенями и
вместе с `assistant_context_chars` в `settings.json` — таблица соответствия в
[docs/11-windows.md](11-windows.md), шаг 6.

Загрузка библиотеки:

```powershell
.\load-library.ps1           # разбор документов, векторы и отчёт — одной командой
```

Что в какую папку класть — [docs/18-library.md](18-library.md).

Остальных сотрудников заводят из того же каталога скриптов:

```powershell
.\users.ps1 -Add ivanov -Role engineer -Name "Иванов И. И." `
    -Department "Отдел радиосвязи" -Team "1 группа"
```

Должности: `owner` (создатель системы), `head` (начальник отдела), `deputy`
(заместитель начальника отдела), `lead` (начальник группы), `senior` (старший
инженер отдела), `engineer` (инженер отдела). Права администратора — у
должностей до начальника группы включительно; письма и отчёты ведут все.
Подробнее — шаг 9 в [docs/11-windows.md](11-windows.md).

## 15.8. Установка на офлайн-машине (Linux)

```bash
./verify.sh
./install-offline.sh /opt/reportgen
```

Отличие одно: llama.cpp под Linux собирается из исходников (они в комплекте,
каталог `llama/llama.cpp`), порядок сборки — в
[docs/10-deployment.md](10-deployment.md). Для сборки нужен CUDA Toolkit, и его
тоже придётся принести с собой: скачайте локальный установщик (`.run`) на
машине с интернетом.

## 15.9. Обновления в офлайне

Если код разворачивался из git-бандла (Git был установлен), обновление —
один файл. На машине с интернетом:

```powershell
cd reportgen
git pull
git bundle create D:\update.bundle --all
```

На офлайн-машине:

```powershell
cd C:\reportgen\app
git pull D:\update.bundle
```

Git-бандл сохраняет историю, поэтому следующий бандл применится поверх без
конфликтов, а неудачное обновление можно откатить.

Если Git на офлайн-машине нет, код разворачивался копированием — тогда
обновление тоже копированием: соберите комплект с `-Only wheels` и скопируйте
`code\reportgen-src` поверх `C:\reportgen\app`.

Если менялись зависимости — соберите новые колёса и поставьте их:

```powershell
# на машине с интернетом
.\pack.ps1 -Destination D:\update -Only wheels

# на офлайн-машине
C:\reportgen\app\.venv\Scripts\python.exe -m pip install --no-index `
    --find-links D:\update\wheels -r C:\reportgen\app\requirements.txt
```

**После обновления переиндексируйте библиотеку** (`ingest --force`, затем
`embed`): правила разбиения текста на токены меняются вместе с кодом, а старый
индекс ищет хуже молча.

Учётные записи на штатные должности переходят сами при первом запуске: первый
по счёту администратор становится создателем системы, остальные — начальниками
отдела, прежние наблюдатели — инженерами отдела. Прав никто не теряет,
разбираться с этим на изолированной машине не придётся. А вот отдел и группу
система не угадает — проставьте их в разделе «Сотрудники».

Модель обновляется копированием нового `.gguf` в `C:\reportgen\models` и
указанием его в `settings.json` (`llm_model_file`). Старую неделю не удаляйте:
новая может оказаться хуже на ваших отчётах.

## 15.10. Что всё-таки придётся принести отдельно

| Что | Когда нужно | Где взять |
|---|---|---|
| Драйвер NVIDIA | Всегда, если ещё не установлен | nvidia.com, локальный установщик (не GeForce Experience) |
| CUDA Toolkit | Только для сборки llama.cpp под Linux | developer.nvidia.com, файл `.run` |
| Обновления Windows | Очень старая система | Windows Update заранее, на машине с интернетом |
| Фирменный бланк `.docx` | Для экспорта по вашему шаблону | Ваш отдел |
| Свой снимок для окна входа | По желанию: в поставке уже есть кадр со спутником и Землёй | Любой JPG или PNG; положите файл рядом с `settings.json` под именем `login-bg.jpg` |

### Каким должен быть фирменный бланк

Бланк — обычный пустой `.docx`, из которого берутся поля страницы,
колонтитулы и стили. Путь к нему указывается в `settings.json`
(`docx_template`). Отчёт собирается стилями Word, а не ручным
форматированием, поэтому в бланке желательно иметь:

| Стиль | Для чего | Если стиля нет |
|---|---|---|
| `Heading 1` … `Heading 4` | Заголовки разделов и подразделов | Заголовок станет обычным жирным абзацем, оглавление Word его не увидит |
| `Table Grid` | Таблицы измерений и параметров | Таблица без линий |
| `Quote` или `Intense Quote` | Цитаты из стандартов и методик | Цитата станет обычным абзацем |
| `List Bullet`, `List Number` | Маркированные и нумерованные списки | Список станет набором абзацев |
| `No Spacing` | Блоки кода и дампов | Между строками появятся отступы |
| `Normal` | Основной текст | — |

Все стили необязательны: без любого из них экспорт не падает, а подставляет
обычный абзац. Проще всего сделать бланк из вашего типового отчёта — удалить
содержимое, оставив колонтитулы, поля и стили.

Проверить бланк можно на тестовом письме: выгрузите отчёт в DOCX и посмотрите
в Word, собирается ли автоматическое оглавление и не съехали ли таблицы.

Драйвер не кладётся в комплект намеренно: он привязан к модели видеокарты и
версии Windows, и скачивать «какой-нибудь» — верный способ получить синий экран
на объекте. Проверьте заранее командой `nvidia-smi`, что драйвер уже стоит и
поддерживает нужную версию CUDA.

## 15.11. Проверка после установки

Комплект развёрнут правильно, когда проходит весь список:

- [ ] `.\verify.ps1` — комплект целый
- [ ] `.\00-check.ps1` — критичных проблем нет
- [ ] `Invoke-Reportgen formats` показывает нужные вам форматы как доступные
- [ ] `tesseract --list-langs` содержит `rus`
- [ ] `nvidia-smi` показывает 12–14.5 ГБ занятой видеопамяти при запущенной модели
- [ ] `http://127.0.0.1:8000/health` отвечает
- [ ] Интерфейс открывается, вход работает
- [ ] Раздел «Дашборд» показывает личный состав и письма в работе
- [ ] Библиотека проиндексирована, поиск по осмысленному запросу возвращает нужное
- [ ] Тестовое письмо (факт-пакет из `examples\cases`) генерируется без ошибок

```powershell
cd C:\reportgen\app

```

## 15.12. Если что-то пошло не так

| Симптом | Причина и что делать |
|---|---|
| `pack.ps1 -Probe` показывает ОШИБКУ у одной строки | Источник переехал. Поправьте адрес в `bundle.example.json` или скачайте файл вручную в `tools` — установщик подхватит его по имени |
| Сборка оборвалась на середине модели | Запустите `pack.ps1` снова: докачка продолжится с того же места |
| `verify.ps1` нашёл повреждённый файл | Скопируйте с диска только этот файл заново. Устанавливать с битым файлом нельзя |
| «колёса собраны для Python 3.11, а установлен 3.12» | Комплект собран на другой версии. Поставьте нужную из `tools` или пересоберите комплект |
| `llama-server.exe не найден после распаковки` | Архив llama.cpp скачался не тот или битый. Проверьте `llama\RELEASE.txt` и пересоберите с `-Only llama` |
| Модель запускается, но работает медленно | Не отключена резервная системная память CUDA — [docs/11-windows.md](11-windows.md), шаг 0 |
| Модель не влезает в видеопамять | Снизьте контекст ступенью ниже (`.\start-all.ps1 -Context 24576` вместе с `assistant_context_chars`), а если не помогло — переключитесь на запасную модель: в `settings.json` укажите `Qwen3-8B-Q5_K_M.gguf` |
| Помощник отвечает без ссылок на источники | Окно контекста переполнено: llama.cpp молча выбрасывает начало промпта вместе с системной инструкцией. Приведите `assistant_context_chars` в соответствие с контекстом — [docs/11-windows.md](11-windows.md), шаг 6 |
| Сканы распознаются в мусор | `tesseract --list-langs` не содержит `rus`. Скопируйте `tessdata\best\rus.traineddata` в каталог `tessdata` Tesseract вручную |
| `Invoke-Reportgen formats` показывает нужный формат недоступным | Соответствующая программа не установилась. Запустите её установщик из `tools` вручную |
