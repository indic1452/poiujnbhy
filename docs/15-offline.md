# 15. Перенос в офлайн: собрать на одной машине, установить на другой

Система изначально рассчитана на изолированный контур. Задача этого документа —
чтобы установка на машине без интернета прошла с первого раза, а не превратилась
в неделю выяснения, какого файла не хватает.

Схема простая: на машине **с интернетом** собирается комплект (один каталог),
он переносится на внешнем диске, на машине **без интернета** проверяется и
разворачивается. Ничего скачивать в процессе установки не нужно — если чего-то
не хватает, установщик останавливается и говорит, что именно доложить.

## 15.1. Что попадает в комплект

| Составляющая | Размер | Зачем |
|---|---|---|
| Колёса Python (`wheels/`) | 40–90 МБ | Зависимости приложения. Ставятся без сети (`pip --no-index`) |
| llama.cpp + библиотеки CUDA (`llama/`) | ~500 МБ | Сервер, который крутит модель на видеокарте |
| Модели GGUF (`models/`) | 12–20 ГБ | Основная модель, эмбеддер, реранкер |
| Установщик Python (`tools/`) | ~25 МБ | Если на офлайн-машине Python не установлен |
| Код (`code/`) | ~5 МБ | Исходники плюс git-бандл для будущих обновлений |
| `manifest.json` | — | SHA-256 каждого файла: проверка целостности после переноса |

Итого 13–21 ГБ. Нужен внешний диск или флешка от 32 ГБ.

**Комплект не архивируется.** Модели GGUF уже сжаты, а архив на двадцать
гигабайт добавляет только риска: одна ошибка чтения — и распаковать нельзя
ничего. Каталог копируется как есть, а целостность проверяется по манифесту.

## 15.2. Главное правило: колёса собираются на такой же системе

Пакеты Python зависят от операционной системы и версии интерпретатора.
Колёса, скачанные на Linux, **не подойдут** для Windows, а собранные для
Python 3.11 не встанут на 3.12.

- Целевая машина Windows → собирайте комплект **на Windows** с той же версией
  Python (`pack.ps1`).
- Целевая машина Linux → собирайте на Linux, желательно того же дистрибутива
  (`pack.sh`).

Установщик это проверяет: в комплекте лежит `wheels/PYTHON-VERSION.txt`, и при
несовпадении установка останавливается с внятным сообщением, а не падает
посреди процесса.

> Скачать колёса под Windows с Linux-машины (`pip download --platform win_amd64`)
> технически можно, но `uvicorn[standard]` тянет `uvloop`, которого под Windows
> нет, и сборщик зависимостей заходит в тупик. Если другого выхода нет, качайте
> без `[standard]`: `fastapi uvicorn httptools websockets python-docx pymupdf
> numpy python-multipart itsdangerous jinja2` — этого достаточно, uvicorn просто
> будет работать на стандартном цикле событий, чуть медленнее.

## 15.3. Шаг 1. Сборка на машине с интернетом (Windows)

```powershell
# Один раз: получить код
git clone <адрес-репозитория> reportgen
cd reportgen\scripts\offline

# Указать, какие модели качать
notepad models.example.json     # проверьте имена репозиториев на huggingface.co

# Собрать комплект
powershell -ExecutionPolicy Bypass -File .\pack.ps1 -Destination D:\reportgen-offline
```

Скрипт скачает всё перечисленное, посчитает контрольные суммы и напишет
манифест. Скачивание моделей идёт через `curl` с докачкой: если связь
оборвалась, просто запустите `pack.ps1` снова — уже скачанное не перекачивается.

Полезные ключи: `-SkipModels` (модели уже скачаны отдельно), `-SkipWheels`,
`-SkipLlama`.

Сразу после сборки проверьте комплект на месте:

```powershell
cd D:\reportgen-offline
.\verify.ps1
```

## 15.4. Шаг 2. Перенос

Скопируйте каталог `reportgen-offline` целиком на внешний диск. Не архивируйте.

При копировании на флешку убедитесь, что файловая система **не FAT32**: там
предел размера файла 4 ГБ, а модель весит больше. Подходят NTFS и exFAT.

## 15.5. Шаг 3. Установка на офлайн-машине (Windows)

```powershell
# Скопируйте каталог с диска, например в C:\install\reportgen-offline
cd C:\install\reportgen-offline

Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
.\verify.ps1                       # проверка после переноса — обязательно
.\install-offline.ps1              # установка в C:\reportgen
```

Что делает установщик:

1. Сверяет контрольные суммы (двадцать гигабайт через флешку регулярно
   приезжают с одним битым файлом; узнать об этом лучше до установки).
2. Проверяет наличие и версию Python, при отсутствии запускает установщик
   из комплекта.
3. Разворачивает код в `C:\reportgen\app`, создаёт структуру каталогов.
4. Распаковывает llama.cpp и раскладывает модели.
5. Ставит зависимости **только из локальных колёс** — pip в сеть не ходит.
6. Создаёт `settings.json` и администратора.

Дальше — обычный порядок из [docs/11-windows.md](11-windows.md):

```powershell
cd C:\reportgen\app\scripts\windows
.\00-check.ps1        # проверка машины
.\start-all.ps1       # запуск модели, эмбеддера, реранкера и интерфейса
```

И загрузка библиотеки:

```powershell
. .\_common.ps1
Invoke-Reportgen ingest      # разбор документов из data\library
Invoke-Reportgen embed       # векторы для смыслового поиска (на GPU)
```

## 15.6. Установка на офлайн-машине (Linux)

```bash
./verify.sh
./install-offline.sh /opt/reportgen
```

Отличие одно: llama.cpp под Linux собирается из исходников (они в комплекте,
каталог `llama/llama.cpp`), порядок сборки — в [docs/10-deployment.md](10-deployment.md).
Для сборки нужен CUDA Toolkit, и его тоже придётся принести с собой: скачайте
локальный установщик (`.run` для Linux) на машине с интернетом.

## 15.7. Обновления в офлайне

Код возится тем же способом. На машине с интернетом:

```powershell
cd reportgen
git pull
git bundle create D:\update.bundle --all
```

На офлайн-машине:

```powershell
cd C:\reportgen\app
git pull D:\update.bundle
.\scripts\windows\01-install.ps1 -SkipDeps
```

Git-бандл сохраняет историю, поэтому следующий бандл применится поверх без
конфликтов. Если зависимости менялись — соберите новый каталог `wheels`
(`pack.ps1 -SkipModels -SkipLlama`) и поставьте:

```powershell
C:\reportgen\app\.venv\Scripts\python.exe -m pip install --no-index `
    --find-links D:\reportgen-offline\wheels -r C:\reportgen\app\requirements.txt
```

**После обновления переиндексируйте библиотеку** (`ingest --force`, затем
`embed`): правила разбиения текста на токены меняются вместе с кодом, а старый
индекс ищет хуже молча.

Модель обновляется просто копированием нового `.gguf` в `C:\reportgen\models`
и указанием его в `settings.json` (`llm_model_file`). Старую неделю не удаляйте:
новая может оказаться хуже на ваших отчётах.

## 15.8. Чего в комплекте нет и что придётся принести отдельно

| Что | Когда нужно | Где взять |
|---|---|---|
| Драйвер NVIDIA | Всегда, если ещё не установлен | nvidia.com, локальный установщик |
| CUDA Toolkit | Только для сборки llama.cpp под Linux | developer.nvidia.com, файл `.run` |
| Visual C++ Redistributable | Редко: Windows без обновлений | microsoft.com |
| OCR (PaddleOCR, tesseract) | Если в библиотеке есть сканы без текстового слоя | Отдельным комплектом колёс и моделей |
| Фирменный бланк `.docx` | Для экспорта по вашему шаблону | Ваш отдел |

## 15.9. Проверка после установки

Комплект считается развёрнутым правильно, когда проходит весь список:

- [ ] `.\verify.ps1` — комплект целый
- [ ] `.\00-check.ps1` — критичных проблем нет
- [ ] `nvidia-smi` показывает 12–14.5 ГБ занятой видеопамяти при запущенной модели
- [ ] `http://127.0.0.1:8000/health` отвечает
- [ ] Интерфейс открывается, вход работает
- [ ] Библиотека проиндексирована, поиск по осмысленному запросу возвращает нужное
- [ ] Тестовый кейс из `examples\cases` генерируется без ошибок верификатора
- [ ] Экспорт в DOCX открывается в Word
- [ ] Помощник отвечает и приводит ссылки на источники

Отдельно стоит прогнать набор тестов — он не требует ни сети, ни модели:

```powershell
cd C:\reportgen\app
$env:PYTHONPATH = "src;tests"
.venv\Scripts\python.exe -m unittest discover -s tests -q
```

Все тесты должны пройти. Если что-то падает — установка неполная, и лучше
разобраться сразу, чем на первом реальном обращении заказчика.
