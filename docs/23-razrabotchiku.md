# Руководство разработчика: что где править, если добавляете своё

Коротко и по делу: куда смотреть и что менять, когда нужно добавить новый код (LDPC, РС, свёрточный,
турбо, ТКБ), скремблер, синхрослово, слой, инструмент стола, протокол или формат файла.
Все пути — от корня репозитория. Если вы здесь впервые, начните с раздела 8 «Карта каталогов».

Два общих правила:

- **Имена часто стоят в строках, а не в импортах.** Файлы `data/ldpc_*.json` читаются по строке
  `ldpc_std._json("dvb")`, модули `setevoy/protokoly/*` подключаются сами при импорте пакета, операции
  стола называются строками в `app.js`. Прежде чем переименовать или удалить что-то, ищите по всему
  репозиторию: `git grep -n "имя"`. Ищите и по части имени тоже.
- **Тесты строятся только на синтетике** с заранее известным ответом (раздел 7). Записи и захваты
  пользователя не кладутся ни в тесты, ни в репозиторий.

## 1. Новый LDPC-код

Есть три пути. Выбирайте по тому, кто будет пользоваться кодом.

| Путь | Правка кода | Кто видит |
|---|---|---|
| Встроенный набор (код стандарта) | да: `data/ldpc_*.json` и при необходимости `ldpc_std.py` | все установки |
| Файл в папке матриц отдела | нет | одна установка, все её пользователи |
| Загрузка через интерфейс | нет | одна установка (JSON в той же папке) |

### 1.1. Встроенный набор

- **Где лежат таблицы:** `src/reportgen/potok/data/ldpc_<семейство>.json`. Читает их
  `ldpc_std._json(имя)`, которая берёт файл `ldpc_{имя}.json`. Файлы `data/*.json` уже входят в пакет
  (`pyproject.toml`, `[tool.setuptools.package-data]`), там ничего добавлять не нужно.
- **Реестр:** `ldpc_std._реестр()`. Внутри него функция
  `добавить(имя, семейство, n, k, скорость, откуда, строить, выколоты, укорочены)` заносит код в
  список. Наружу реестр отдают `ldpc_std.список()`, `ldpc_std.есть(имя)`, `ldpc_std.матрица(имя)` и
  `ldpc_std.схема(имя)`.
- **Форматы записей.** Ключ записи — имя кода. Это же имя — второе слово слоя: `ldpc dvb-s2-64800-48600`.
  - *Базовая матрица сдвигов (QC):* поля `база` (ряды сдвигов, −1 — нулевой блок), `Z` (у G.hn — `b`,
    у DOCSIS — `L`), а также `n`, `k`, `скорость`, `семейство`, `откуда`. Так устроены `ldpc_wifi.json`,
    `ldpc_ghn.json`, `ldpc_docsis.json`, `ldpc_80211ad.json` и `ldpc_vosstanovlennye.json` (у последнего
    есть ещё `данные_с`). Матрицу строит `ldpc_std._квазициклическая` через `ldpc.из_прототипа`.
  - *Таблица адресов DVB:* поле `строки` (адреса проверок для групп по 360 бит), `n`, `k`. Так устроены
    `ldpc_dvb.json` и ATSC тип B в `ldpc_atsc.json`. Матрицу строит `ldpc.из_адресов`.
  - *Номера единиц по строкам H:* поле `строки`. Так устроены `ldpc_prochie.json` и `ldpc_dtmb.json`
    (у DTMB есть ещё `данные_с` и `выколоты`). Матрица — `ldpc.Матрица` или `ldpc_std._по_строкам`.
  - *Особые форматы со своим построителем:* `ldpc_nr.json` (поле `графы`), `ldpc_ccsds.json` (`ar4ja`,
    `c2`, `tc`), `ldpc_wimax.json` (`матрицы`), `ldpc_dvbs2x.json` (`vlsnr`, `перемежения`),
    `ldpc_kitay.json` (`тройки`, модуль `ldpc_kitay.py`, функции `ldpc_kitay.записи` и
    `ldpc_kitay.матрица`), `ldpc_fldpc.json` (модуль `ldpc_flex.py`).
- **Как добавить:**
  1. Код в формате уже существующего файла: допишите запись в этот JSON. Записи `dvb`, `wifi`,
     `prochie`, `ghn`, `docsis`, `atsc`, `dtmb`, `80211ad` и `vosstanovlennye` реестр подхватывает
     циклом, код менять не нужно.
  2. Новое семейство: создайте `data/ldpc_новое.json` и напишите построитель по образцу
     `ldpc_std._ghn` или `ldpc_std._dtmb`. Затем добавьте в `_реестр()` цикл
     `for имя, к in _json("новое").items(): добавить(...)`.
- **Схема передачи:** строки `выколоты` и `укорочены` (вид «0-191,1000-1023»). Перемежение бит перед
  модулятором задаёт `ldpc_std.перемежения(имя)`: для DVB-S2 это `ПЕРЕМЕЖЕНИЯ_DVB_S2`, для S2X — поле
  `перемежения` в `ldpc_dvbs2x.json`.
- **Первоисточник** запишите в поле `откуда` (стандарт, раздел, страница) и в опись `istochniki/README.md`.
  В репозитории из `istochniki/` лежит только опись, самих файлов нет.

### 1.2. Как новый код увидит автомат (опознание по матрицам)

- **Опознаватель по синдрому:** `ldpc_opoznanie.опознать(биты, …)` и `ldpc_opoznanie.найти(…)`.
  Перебирает `ldpc_opoznanie.варианты()`, то есть все `ldpc_std.подходящие(None)` вместе с их
  перемежениями. Новый встроенный код попадает в перебор сам.
- **Очередь перебора:** `ldpc_opoznanie.ОЧЕРЕДЬ` — кортеж префиксов имён (`"dvb-s2-"`, `"nr-"`, …).
  Код без подходящего префикса идёт последним, и при коротком сроке до него может не дойти. Если код
  важный, добавьте префикс в `ОЧЕРЕДЬ`.
- **Кэш наборов проверок:** `ldpc_opoznanie._путь_кэша()` — файл `.npz` во временной папке. Ключ кэша
  складывается из размеров и времени изменения файлов `ldpc*.py` и `data/ldpc_*.json`, поэтому после
  правки JSON кэш обновится сам. Переменная окружения `REPORTGEN_LDPC_NABORY`
  (`ПЕРЕМЕННАЯ_НАБОРОВ`) задаёт свой путь к кэшу; значение «нет» отключает кэш.
- **Вызов из автомата:** `razbor._ldpc` (опознаватель плюс `ldpc.найти_по_матрицам` для загруженных
  матриц) и `razbor._по_матрицам`. Когда и сколько пробовать, задают ключи профиля `razbor.ПРОФИЛИ`:
  `"встроенные_ldpc"` и `"ldpc_срок"`.
- **Окно «LDPC» на столе:** список «Тип LDPC кода» строит `ldpc_katalog.типы()`. Новое семейство нужно
  вписать в список `семейства` внутри этой функции (тип, префикс, источник), иначе в списке типов его
  не будет. Сейчас там, например, нет КНР (ABS-S, CMMB, BeiDou) и CASC.
- **Ручной слой:** `ldpc ИМЯ [выколоты …] [укорочены …] [перемежение …] [начало N [шаг M]]`. Его
  разбирает ветка `ldpc` в `razbor.снять_вручную`, которая зовёт `ldpc.из_указания`.

### 1.3. Восстановленные коды (`ldpc_vosstanovlennye.json`)

- Здесь лежат коды, которые восстановлены по записи и сделаны встроенными. Поля записи:
  `семейство`, `n`, `k`, `скорость`, `Z`, `данные_с`, `база`, `откуда`. Читает их
  `ldpc_std._восстановленный`, в реестр заносит цикл в `_реестр()`.
- Синтетика для такого кода — `tests/casc_sintez.py`. Он читает тот же JSON (константа `CASC_ДАННЫЕ`).
- Автомат умеет восстанавливать H сам (`razbor._ldpc_восстановление` → `ldpc_vosst.восстановить`).
  Найденную матрицу он кладёт файлом alist в папку отдела (`ldpc_vosst.сохранить`), а **не** во
  встроенный набор. Чтобы код стал встроенным, перенесите его базовую матрицу в
  `ldpc_vosstanovlennye.json`.

### 1.4. Загрузка матрицы без правки кода

- **Папка матриц отдела:** `<папка данных>/ldpc`. Её создаёт `ldpc.подготовить_каталог`; вызовы стоят
  в `web/app.py`, `cli.py` и `potok/zadaniya.py`. Там же лежит памятка `_ПРОЧТИ.txt` (текст —
  `ldpc.ПАМЯТКА`). Текущий путь хранится в `ldpc.КАТАЛОГ`.
- **Файл в папке:** расширения перечислены в `ldpc.РАСШИРЕНИЯ` (.alist .qc .base .adr .h .txt). Вид
  определяет `ldpc.разобрать_файл`:
  - alist;
  - строка «Z = 96» и ряды сдвигов;
  - строки «n = …» и «k = …», затем адреса;
  - ряды из 0 и 1.

  Примечания в файле: `# выколоты:`, `# укорочены:`, `# перемежение: 1367 | 8PSK 012`, `# данные:`,
  `# откуда:`.
- **Через интерфейс (API в `src/reportgen/web/api.py`):**
  - `POST /api/potok-ldpc-files` — положить файл в папку. Перед сохранением файл разбирается.
  - `POST /api/potok-matrices` — текст матрицы. Параметры: `kind` (alist | базовая | адреса), `z`,
    `n`, `k`, `punctured`, `shortened`. Сервер вызывает `ldpc.загрузить` и `ldpc.сохранить`, в папку
    ложится JSON.
  - `GET /api/potok-matrices`, `DELETE /api/potok-matrices/{name}`, `GET /api/potok-ldpc-types`.
- **Чьё имя главнее:** загруженный JSON, затем файл отдела, затем встроенный код (`ldpc.прочитать`,
  `ldpc._встроенная`). Автомат пробует все матрицы из папки (`ldpc_opoznanie.наборы_загруженных`).
- **Формат alist:** строка «n m», затем наибольшие веса столбца и строки, затем веса всех столбцов,
  затем веса строк, затем номера единиц по столбцам (с 1, дополнены нулями), затем по строкам. Читает
  `ldpc.из_alist`, пишет `ldpc.в_alist`.

**Тесты:** `tests/test_potok_ldpc_std.py`, `test_potok_ldpc_opoznanie.py`, `test_potok_ldpc_semeystva.py`,
`test_potok_ldpc_vosst.py`, `test_potok_ldpc_kitay.py`; синтетика — `tests/ldpc_potoki.py`.

## 2. Рид — Соломон, БЧХ, свёрточные, турбо, ТКБ; каталог кодов

### 2.1. Рид — Соломон и БЧХ

- **Поле и декодер:** `potok/rs_bch.py`: `поле`, `примитивные`, `синдромы`, `исправить`,
  `закодировать_рс`, `исправить_со_стираниями`; слепое опознание — `опознать`.
- **Стандарты с перемежением символов:** `rs_peremezhenie.ПРОФИЛИ`. Каждый `Профиль` содержит имя,
  описание, N, k, m, поле, fcr, перемежение и источник (DSS, DVB, система C, ATSC, J.83B). Для IESS есть
  отдельный `ПРОФИЛИ_IESS`. Коды IESS записаны в `iess.КОДЫ`, поле — в `iess.ПОЛЕ`, первый корень — в
  `iess.ПЕРВЫЙ`.
- **Отдельные стандарты:** DVB RS (204, 188) — `potok/dvb.py`; OTN RS (255, 239) — `potok/otn.py`;
  двойной базис CCSDS — `dlinnye._TAL`.
- **Короткие блочные коды:** названия по (n, k) — `kod.ИЗВЕСТНЫЕ`.
- **Ручные слои:** «рс N K [поле 0x11D] [fcr F] …», «рс вслепую», «рс перемежение …». Это ветки
  `рс`/`rs` в `razbor.снять_вручную`; слой с перемежением ведёт в `rs_peremezhenie.снять_слоем`.
  Слепой РС живёт в `rs_slepoy.py` (файл сейчас в параллельной работе).

### 2.2. Свёрточные коды

- **Запись многочленов:** восьмерично, как в стандартах (171/133, старший бит — текущий вход). Внутри
  программы запись обратная, переводит `svyortka.зеркало(g, K)`, обратно в текст — `svyortka.запись`.
  Аналитик везде видит и вводит запись стандартов.
- **Известные пары:** `kod.СВЁРТОЧНЫЕ`. Материнские коды для выкалывания — `vykalyvanie.СТАНДАРТНЫЕ`,
  шаблоны выкалывания — `vykalyvanie.ШАБЛОНЫ_СТАНДАРТОВ`, шаблоны НСК — `razbor.НСК_ШАБЛОНЫ`.
- **Слои:** «свёрточный 171/133 K=7 [кольцо L]» (кольцо — циклический хвост LTE) и
  «выколотый 171/133 K=7 шаблон 1101».

### 2.3. Турбокоды (TCC) — `potok/turbo_std.py`

- **UMTS:** `UMTS_РСК`, `UMTS_ПРОСТЫЕ`, `UMTS_T`, функция `umts`.
- **LTE:** `LTE_QPP`, функция `lte`. Сверочная таблица QPP — `tests/lte_qpp_36212.txt`, её читает
  `tests/turbo_koder.py`.
- **CCSDS:** `CCSDS_K`, `CCSDS_ASM`, функция `ccsds`.
- **DVB-RCS:** `RCS_ПАРАМЕТРЫ`, `RCS_КОЛЬЦО`, `RCS_ВЫКАЛЫВАНИЕ`, функция `rcs`.
- Составляющие коды для слепого поиска — `СОСТАВЛЯЮЩИЕ`.
- Слой «tcc umts K …» разбирает `turbo_std.снять`.

### 2.4. ТКБ (турбокод блочный) — `potok/tpc_rezhimy.py`

- **Описание режима:** `Режим` (`ид`, `оси`, `укор`, `бит_укор`, `нулей`, `гипер`, `выколото`, `кадр`,
  `скорость`, `модем`, `источник`, `метка`).
- **Таблица режимов:** `КАТАЛОГ = _каталог()`. Функции-группы — `_aha4501`, `_ofdm` и другие. Новый режим
  — это `Режим(...)` внутри `_каталог()` (или новая функция-группа, вызванная из него). Обязательно
  заполните `источник` и `метка`: «Ф» — из файла, «А» — арифметика, «Г» — гипотеза, «С» — только со
  снимка экрана.
- **Многочлены Хэмминга:** `МНОГОЧЛЕНЫ_ХЭММИНГА`.
- Режим по имени ищет `режим(ид)`. Слой: «ткб режим ИМЯ …».
- Синтетика — `tests/tkb_koder.py`. Тест `test_potok_tpc_rezhimy.py` сейчас в параллельной работе.

### 2.5. Каталог кодов и рабочие таблицы — в чём разница

- **Каталог** — справочник. В нём:
  - `src/reportgen/potok/data/kody_katalog.json` — 1747 записей, ключ `записи`;
  - таблицы `src/reportgen/potok/data/kody/<область>/…`;
  - модуль `potok/katalog_kodov.py`: `найти`, `запись`, `таблица`, `сводка`; из командной строки —
    `python3 -m reportgen.potok.katalog_kodov`;
  - описание — `docs/22-kody.md`; тест — `tests/test_potok_katalog_kodov.py`.
- **Автомат и стол каталог не читают.** Проверено через `git grep`: в `src/` каталог импортирует только
  сам `katalog_kodov.py`. Рабочие значения лежат в модулях из 2.1–2.4 и в `data/ldpc_*.json`.
- **Вывод:** запись в каталоге ещё не учит автомат снимать код. Чтобы автомат снимал, правьте рабочую
  таблицу и добавляйте тест. В записи каталога после этого поставьте поле `в проекте` = «есть».
- **Новая запись в каталог:** поля описаны в `docs/22-kody.md`, п. 22.1. Тест
  `test_таблицы_на_месте_и_читаются` проверяет, что таблицы, на которые ссылается запись, существуют, и
  что каждый `data/kody/**/*.json` читается как JSON.

## 3. Скремблер, синхрослово, новый вид находки

### 3.1. Скремблер и ПСП — `potok/skrembler.py`

- **Таблицы:**
  - `ИЗВЕСТНЫЕ` — имя → отводы мультипликативного скремблера (степени x⁻ᵏ);
  - `ИЗВЕСТНЫЕ_ПСП` — (отводы, начальное состояние) → имя аддитивной ПСП со сбросом на кадре;
  - `РАНДОМИЗАТОР_802_16`.
- **Поиск:** `найти`, `найти_по_кадру`, `блоковая_псп`.
- **Снятие:** `снять`, `аддитивный`, `снять_по_кадру`.
- **Слои:** «скремблер a,b», «аддитивный отводы …», «псп …». Их разбирают ветки в
  `razbor.снять_вручную` (`_аддитивный_вручную`, `_псп_вручную`). По всему файлу эти слои идут кусками
  через класс `_Скремблер` и функцию `_аддитивный` в `potokovo.py`.

### 3.2. Кадрирование и синхрослово

- **Известные синхрокомбинации:** `sinhro.известные()`. В список входят FAS E1 (`cikl.FAS`), флаг HDLC
  (`hdlc.ФЛАГ`), PDH (`pdh.ИЕРАРХИИ`), маски GFP (`gfp.МАСКИ`), `ASM_CCSDS` и SDH/OTN.
- **Проще всего добавить слово радиосистемы** строкой `(имя, значение, бит)` в `sinhro.ДРУГИЕ_СЛОВА`.
  Название найденного слова подставит `sinhro.известная`, а список слов отдаёт API (в `api.py` есть
  вызов `sinhro.известные()`).
- **Цикл и кадры:** поиск — `cikl.найти`, `cikl.кадры`. Ручные слои — «синхро СЛОВО» и
  «кадры СЛОВО длина N» (`sinhro.синхронизировать`, `sinhro.выровнять`; кусками — `_Синхро`, `_Кадры`
  в `potokovo.py`).
- **Свой вид кадров** (как `dmr.py`, `p25.py`, `nxdn.py`): модуль с функцией
  `найти(биты) -> Находка | None`. Подключение — в `razbor._проверяемые` по образцу соседних блоков:
  - проверка `"кадр" in мимо`;
  - при удаче — `ветвь.проверяемая(...)`;
  - при неудаче — строка в `ветвь.не_найдено`.

### 3.3. Новый вид находки в автомате (`potok/razbor.py`)

- **Модель находки:** `nahodka.Находка`. Поля: `уровень`, `что`, `уверенность`, `мера`, `подробно`,
  `дальше`, `вид_дальше` («биты», «байты», «кадры», «притоки»), `сверка`, `путь`, `свойства`.
- **Уровни.** `уровень` — это строка: «код», «скремблер», «цикл», «плоскость», «канальный», «сетевой»,
  «вставка», «вручную» и другие.
  - С какого уровня начинать разбор — `razbor.УРОВНИ_СТАРТА`; что пропускается — `ПОИСКИ_УРОВНЯ`.
  - Детектор относится к уровню по подстроке своего имени — `УРОВЕНЬ_ДЕТЕКТОРА`.
- **Куда подключать поиск:**
  - *Находка, которая доказывает себя сама* (CRC, синхрослово, FCS) — в `razbor._проверяемые`:
    1. вызвать `модуль.найти(выборка)`;
    2. при удаче — `ветвь.проверяемая(найдено, путь)`;
    3. если у находки есть выход, разобрать его дальше:
       `ветвь.влить(_ступень(найдено.дальше, глубина, _дальше(путь, "…"), б))`;
    4. если не нашлось — строка в `ветвь.не_найдено` (без неё не отличить «нет» от «не смотрели»).
  - *Преобразование* (код, скремблер, перемежение) — кортеж `(имя, lambda: …, "после снятия …")` в
    список `razbor._детекторы`. Дешёвые детекторы ставьте раньше дорогих.
- **Свойства находки, нужные для работы по всему файлу и для стола:**
  - `свойства["слой"]` — строка ручного слоя в той грамматике, которую понимает `снять_вручную`;
  - `свойства["перед"]` — слои, которые снимаются раньше него (например, `["реверс 8"]`);
  - `свойства["кадр"]` — длина кадра (ТКБ и TPC в кадрах, цикл в `cikl.py`);
  - `свойства["кадры_слой"]` — строка разборщика кадров для пересчёта по всему файлу. Её разбирает
    `kadry_ves.разобрать_слой`. Виды: `hdlc`, `ppp`, `slip`, `atm`, `gfp`, `bbframe`, `ip`, `pcap`,
    `ip-поток`. Читают свойство `kadry_ves.слой_находки` и `kadry_ves.пункты_плана`;
  - у цикла — `слои_нагрузки` (вырезка нагрузки).
- `слой` и `перед` читают `razbor.слои_этапа` (этапы по всему файлу) и `razbor.слои_находки` (шаг стола).
- **Если слоя нет,** этап считается только по выборке (начало файла), и цепочка этапов по всему файлу
  на нём останавливается.

## 4. Новый ручной слой

### 4.1. Грамматика — `razbor.снять_вручную(биты, указание)`

- **Разбор указания:**
  - первое слово — вид слоя: `вид = слова.split()[0]`;
  - все числа указания — в `числа`;
  - именованные параметры — через `_число_после(слова, "начал")`.
- **Новая ветка** — `elif вид == "…":`, перед последним `else: raise ValueError("не понимаю указание …")`.
- **Что вернуть:** `(ряд, Находка(уровень="вручную", …))`; сведения кладите в `подробно` и `свойства`.
- **Большой слой** вынесите в свой модуль с функцией `снять(биты, слова) -> (ряд, подробно)`, как
  сделано в `turbo_std.снять`, `gfp.снять` и `rs_peremezhenie.снять_слоем`.
- **Строка документации `снять_вручную`** служит справочником грамматики: допишите туда новый слой.

### 4.2. На столе

- `rastr.применить(биты, шаги)` выполняет шаги вида `{"вид": "слой", "слой": "…", "вкл": True}`
  через `снять_вручную`. Проверка шагов — `rastr.проверить_шаги`, подпись шага — `rastr.описать_шаг`.

### 4.3. По всему файлу — `potokovo.выполнить(источник, шаги, куда)`

- **Массив до `В_ПАМЯТИ_ДО` бит** обрабатывается целиком в памяти, через `rastr.применить`.
- **Массив больше — кусками по `КУСОК_БИТ`.** Варианты для нового слоя:
  - *Слой можно применять кусок за куском, итог как у целого ряда* (побитовый слой или слой с малым
    состоянием): напишите класс-наследник `_Шаг` (или `_Простой`, `_ПоГруппам`) и ветку в
    `potokovo.потоковый`.
  - *Слою нужен весь ряд, но куски можно обрабатывать независимо* (кодовые слова или кадры сами
    находят начало): добавьте первое слово слоя в кортеж `potokovo.КУСКАМИ`. Проверяет это
    `_кусками_можно`.
  - *Ни то ни другое:* на большом массиве слой не выполнится, и человек увидит объяснение почему.
- **Требование:** итог по кускам должен совпадать с итогом в памяти бит в бит.

### 4.4. Связь с этапами автомата

Путь от находки до пересчёта всего файла:

1. Находка с `свойства["слой"]`.
2. `razbor.слои_этапа(находка)`.
3. `razbor.шаги_по_этапам(находки)` — шаги от потока этапа k−1 к этапу k.
4. `zadaniya.план_всего_файла(находки, список, снять)` — список `{номер, шаги}`. Слои, снятые вручную
   при запуске (`снять`), идут первыми этапами.
5. `zadaniya.пересчитать_этапы` вызывает `potokovo.выполнить`.

Кадры и пакеты пересчитываются отдельно: `kadry_ves.пункты_плана` и `kadry_ves.пересчитать_этап`.

**Проверить слой из командной строки:**
`PYTHONPATH=src python3 -m reportgen potok файл.bin --снять "слой"` (`cli.cmd_potok`, ключ `--снять`).

## 5. Новый инструмент стола

### 5.1. Меню — `ОПЕРАЦИИ_СТОЛА` в `src/reportgen/web/static/app.js`

Пункт меню: `{ id, раздел, имя, вид, … }`. Поле `вид` бывает трёх видов.

- **`'слой'`** — снимает слой и делает новый массив.
  - Шаблон с полями: `слой: 'фм {k} поворот {r}…'`.
  - Описание полей: `поля: [{ ключ, подпись, по, флаг, текст, выбор, приставка }]`.
  - Цепочка вызовов: `слойВМассив` → `POST /api/potok/{job}/derive` (там шаги проверяет
    `rastr.проверить_шаги`) → в задании `zadaniya.выполнить_шаги` → `potokovo.выполнить` →
    `rastr.применить` → `снять_вручную`.
- **`'инструмент'`** с полем `tool: 'имя'` — ищет и пишет итог в журнал.
  - Цепочка вызовов: `POST /api/potok/{job}/tool` → `stol_raschety.инструмент` → `rastr.инструмент`.
  - В `rastr.инструмент` нужна своя ветка `if имя == "…"`.
- **`'действие'`** с полем `сделать: 'ключ'` — своё окно и свои запросы. Нужен свой
  `case 'ключ':` в функции `действие(о, у, значения)` в `app.js`.

**Место в меню.** Раскладка — `КАТЕГОРИИ_СТОЛА`. Пункт, которого там нет, сам встаёт в конец категории
своего раздела (`РАЗДЕЛ_В_КАТЕГОРИЮ`). Там же рядом:

- горячие клавиши — `КЛАВИШИ_ОПЕРАЦИЙ`;
- синонимы для поиска — `СИНОНИМЫ_ОПЕРАЦИЙ`;
- избранное по умолчанию — `ИЗБРАННЫЕ_ПО_УМОЛЧАНИЮ`;
- вкладки окна «Декодер» — `ВКЛАДКИ_КОДОВ` (поле `пункты` — список id операций).

### 5.2. Сервер

- **Маршруты** — `src/reportgen/web/api.py`. Роутер `router = APIRouter(prefix="/api")`, маршрут
  объявляется декоратором `@router.post("/potok/{job_id}/…")`. Права проверяют `require_user` и
  `_файл_бит_или_400`.
- **Тяжёлый расчёт** оформите функцией уровня модуля в `potok/stol_raschety.py`. Вызывайте её через
  `_посчитать(request, user, stol_raschety.функция, _источник(request, job_id, этап), …)`: так расчёт
  идёт в отдельном процессе-исполнителе и не держит сервер.
- **Расчёты по растру** (сетка, периоды, столбцы) — `potok/rastr.py`: `сетка`, `периоды`,
  `поиск_периода`, `столбцы`, `инструмент`.

### 5.3. Тесты

- `tests/test_potok_stol_menyu.py`. В нём `ПРЕЖНИЕ_ПУНКТЫ` — список id, ни один из которых не должен

- Ещё: `tests/test_potok_stol.py`, `tests/test_potok_stol_polya.py`.

## 6. Анализ пакетов: новый протокол и новый формат входа

### 6.1. Что где лежит в `src/reportgen/setevoy/`

- **`razbor.py`** — основа.
  - Вход: `разобрать_пакет`, таблица `КАНАЛ_В_РАЗБОРЩИК` (тип канала → разборщик первого уровня).
  - Разборщики уровней: `ethernet`, `ipv4`, `ipv6`, `по_протоколу`.
  - Таблицы: `ETHERTYPE`, `IP_ПРОТОКОЛЫ`.
  - Таблицы регистрации: `ДОП_ETHERTYPE`, `ДОП_IP`, `ДОП_LLC`, `ДОП_SCTP_PPID`, `ДОП_SCTP_ПОРТ`,
    `ДОП_PPP`, `ДОП_ETHERNET`, `ДОП_УРОВНИ`.
- **`prilozh.py`** — прикладной уровень: `ПОРТЫ_TCP`, `ПОРТЫ_UDP`, `TLS_ПОРТЫ`, `ПЕРЕД_ПОРТАМИ`, `КАК`
  («разбирать как»), `ЭВРИСТИКИ_TCP`, `ЭВРИСТИКИ_UDP`.
- **`protokoly/*.py`** — группы протоколов. Каждый модуль подключается сам: `protokoly/__init__.py`
  импортирует всё через `pkgutil.iter_modules`, а `razbor.py` в конце импортирует `protokoly`.
- **`pole.py`** — модель разобранного пакета: `Пакет`, `Уровень`, `Поле`, исключение `Мало`, чтение
  чисел `u8`, `u16`, `u32`, `mac`, `ip4`.
- **Прочее:**
  - `obshee.py` — состояние захвата между пакетами, декоратор `действие`;
  - `filtr.py` — фильтры;
  - `statistika.py` — статистика;
  - `dekodirovat_kak.py` — «Декодировать как»;
  - `vygruzka.py`, `obekty.py` — выгрузки и объекты;
  - `hranilishe.py` — хранилище пакетов на диске.

### 6.2. Новый протокол

1. **Где писать.** Новый файл в `setevoy/protokoly/` подхватится сам. Можно и дописать в модуль
   подходящей группы.
2. **Разборщик.** Для прикладного уровня — `def имя(р: Разбор, м: int, конец: int) -> bool`, вернуть
   True, если данные его. Для EtherType — `(р, м)`.
3. **Внутри разборщика:**
   - `у = р.уровень("ИМЯ", "Полное имя", м)`;
   - `р.нужно(м, n)` — если байт не хватает, бросит `Мало`, и пакет пометится «пакет оборван»;
   - поля дерева: `у.поле("Подпись", "имя.поле", текст, смещение, длина, сырое, родитель=п)`.
     Вложенность строится через `родитель` (поле `дети`). Ключ поля пишите как в Wireshark
     (`diameter.cmd.code`) — по нему работает фильтр;
   - `у.итог = "…"`; затем `р.нагрузка(...)` или вызов следующего разборщика.
4. **Регистрация — в конце модуля:**
   - `ДОП_ETHERTYPE[0x8902] = cfm` (так же `ДОП_IP`, `ДОП_LLC`, `ДОП_SCTP_PPID`, `ДОП_SCTP_ПОРТ`,
     `ДОП_PPP`);
   - `prilozh.ПОРТЫ_UDP.setdefault(порт, ф)` (или `ПОРТЫ_TCP`);
   - `prilozh.КАК["udp"]["Имя"] = ф` — пункт «разбирать как»;
   - `prilozh.ЭВРИСТИКИ_UDP.append(ф)` — угадывание без порта;
   - `ДОП_УРОВНИ["ИМЯ"] = "прикладной"` — уровень в дереве протоколов.

   Готовый пример — регистрация в конце `protokoly/oam.py`.

### 6.3. Новый формат входа

- **Анализ пакетов — `setevoy/chtenie.py`:**
  - `прочитать_захват` пробует pcap, затем pcapng, затем .sig;
  - `вид_по_началу` узнаёт вид по сигнатуре (`PCAP_МАГИИ`, `PCAPNG_МАГИЯ`);
  - `ЧтецЗахвата` читает поточно, файл любого размера;
  - тип канала: `КАНАЛЫ` (номер LINKTYPE → имя), затем `razbor.КАНАЛ_В_РАЗБОРЩИК` (имя → разборщик).
    Новый тип канала — строка в обеих таблицах.
- **Разбор потоков — `potok/chtenie.py`:**
  - `прочитать` выбирает вид по расширению: текст (`.txt`, `.hex`, `.bits`) → биты; `РАСШИРЕНИЯ_SIG`
    (`.sig`, `.dpo`) → `разобрать_sig`; всё прочее — сырой поток;
  - для больших файлов: `разметка_sig`, `разобрать_sig_файл`, `биты_текста_в_файл`.

### 6.4. Тесты

- `tests/test_setevoy_*.py`.
- Синтетика: `tests/setevoy_sintez.py` (`eth`, `ip`, `udp`, `tcp`, `pcap`, `pcapng`),
  `tests/pakety_generator.py`, `tests/obekty_sintez.py`.
- Сверка с эталоном pycrate — `tests/test_setevoy_etalon_3gpp.py`; без pycrate тест пропускается.

## 7. Тесты

- **Где:** `tests/`, стандартный `unittest`. pytest тоже их понимает (`[tool.pytest.ini_options]` в
  `pyproject.toml`). Каждый тест первым импортирует `tests/_bootstrap.py`
  (`import _bootstrap  # noqa: F401`), который добавляет `src` в путь.
- **Синтетика:**
  - `tests/potok_sintez.py` — IP, HDLC, E1, скремблер, Хэмминг, свёрточный, PDH, DVB, QC-LDPC, турбо,
    РС, GFP, ATM;
  - для отдельных тем: `kanal_sintez.py`, `casc_sintez.py`, `gfp_sintez.py`, `rs_peremezhenie_sintez.py`,
    `ldpc_potoki.py`;
  - кодеры: `tkb_koder.py`, `turbo_koder.py`, `gfp_koder.py`;
  - пакеты: `setevoy_sintez.py`, `obekty_sintez.py`, `pakety_generator.py`, `pakety_smes.py`.
- **Как прогнать:**
  - всё — `make test`;
  - один набор — `make test TESTS=test_potok_ldpc_std`;
  - один класс или тест — `PYTHONPATH=src:tests python3 -m unittest test_potok_ldpc_std.Класс.test_имя -v`;
  - через pytest — `python3 -m pytest tests/test_potok_ldpc_std.py -k имя`;
  - проверка стиля — `make lint` (ruff и compileall).
- **Правило — только синтетика.** Поток собирается кодом теста, ответ известен до бита. Файлы
  пользователя (записи, захваты, содержимое `var/`) в тесты и в репозиторий не кладутся. Если тесту
  нужны первоисточники из `istochniki/`, а их нет, он пропускается через `skipTest`, как
  `test_potok_ldpc_kitay.py`.
- **Функции `app.js`** проверяются в node (`test_potok_sessii.функции_js`); если node нет, такие тесты
  пропускаются.
- **Фикстуры в репозитории:** `tests/powershell/itu/*.html` (для `test_offline.py`) и
  `tests/lte_qpp_36212.txt`.
